## 二、聚合原则（四条硬纪律）

1. **组合，而非复制**——脑核不做 vendoring/fork：以依赖引入，版本升级走包管理器；
   身体件不做原地链接：筛选后**导出副本**在本仓固化（上游保持私有主体）。
2. **单向引入**——上游是真源；本仓的修改若要回流，走上游仓的纪律流程（不得本仓直改再反向同步）。
3. **逐件筛选**——任何身体侧件入仓前，逐件过：
   - **内容政策清单**（无凭据 / 无本机路径字面量 / 无个人隐私 / 无第三方受限内容）；
   - **隐私清单**（不含私有内容资产：记忆数据、私有模块名、私有算法细节）；
   - 筛选记录随件入档（`docs/intake/` 登记表）。
4. **干净历史**——本仓不迁移任何上游的 git 历史（上游历史含私有提交）；
   首次引入即初始提交，来源以上游仓+版本号标注。

## 三、分层（轻核 / 重载）

```
lingshu
├── core   轻核：记忆与协议——零重依赖可裸跑（白箱纪律区）
├── sense  感知：视觉 / 时空（重载依赖：numpy 等）
├── gen    生成：确定性渲染与读回（重载可选）
└── world  世界模型：推演循环与物理沙盒（重载可选）
```

- **轻核承诺**：`core` 不因本仓的「完整」而增重——可单独安装、单独运行；
- **重载声明**：`sense`/`gen`/`world` 的依赖与模型资产按需安装（extra 形态），
  安装体积与依赖深度如实在各件 README 登记。

- 记忆数据（认知图真源、会话记录、任何 `data/`）**永不入本仓**；
