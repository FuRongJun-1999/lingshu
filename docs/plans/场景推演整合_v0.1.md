# 场景推演整合 v0.1（第 8 项 · 后端整合件）

状态：`needs-owner-decision`。本件是独立新增消费入口，不接管现有默认调用链；
最终分位、接口命名和角色可见性规则由本项目理论核确认。第 9 项的可选插件安装另件推进。
安装后有 demo/local/brain 三种 CLI 来源，完整步骤见 [运行与交付](../scenario_usage.md)。

## 解决的问题与依据

公开仓已有时空节点、条件空间、因果边、3D 世界重建以及 MCP 脑适配器；
脑端已有 `roleplay / role:<id> / roleplay:role / session:<id> / turn:<who>`。
缺的是消费层整合入口：一个任务选取的记忆怎样共享给角色、世界、故事、历史与因果任务，
同时保留作用域、来源、资格与推演边界。

本件沿用 [世界模型总纲](../theory/世界模型与语义时空图_完整理论整理与实现路线.md)
的条件化知识与白箱原则，以及协议仓
[子知识虚拟化设计](https://github.com/FuRongJun-1999/CommonTrustProtocol/blob/main/docs/虚拟化世界观-子知识与白箱判定.md)
的 `sub-knowledge + role:<id>` 隔离纪律。身体侧适配器归属和 MCP 通道沿用
`lingshu.world.brain_store`，不复制脑代码、角色模板或记忆存储。

## 可运行接口

```python
from lingshu.world.scenario import ScenarioContext

# 显式选取现有本地图的记录；每个 id 只读一次，不调用 recall、不增加访问计数。
context = ScenarioContext.from_store(
    memory.store, [role_id, lore_id, action_id, outcome_id],
    role_id="alice", session_id="conversation-1",
)
role_material = context.view("roleplay")
world_state = context.view("world")
outline = context.view("story")
historical_material = context.view("history")
causal_candidates = context.view("causal", start_id=action_id, end_id=outcome_id)

# 已安装 numpy/Pillow（如 .[full]）时，复用现有 WorldModel。
model = context.to_world_model()
```

脑端调用（必须显式隔离/指定库根；身份参数沿用脑端配置）：

```python
from lingshu.world.brain_store import connect
from lingshu.world.scenario import ScenarioContext

agent = connect(root=target_root, pythonpath=brain_package_path, extra_env=identity_env)
try:
    context = ScenarioContext.from_brain(
        agent.store.client, "灯塔场景", k=64,
        role_id="alice", session_id="conversation-1",
    )
    material = context.view("roleplay")
finally:
    agent.store.client.close()
```

脑端沿用既有 `cg(op=read)`，现实空间实体的现值沿用 M1 的
`stg(op=state_chain, slot=状态)` 投影，附原始状态事件证据；资格 `state` 原样保留。
不存在单一现值或投影超限时显式留缺口，不依赖私有身体生成后端。
脑端召回可能维护其自身统计，不宣称整个 MCP 读取零落盘。
本层的角色/会话过滤是消费作用域，**不是身份认证边界**；脑端授权、tenant 与
clearance 仍由 MCP/脑端执行，本地 store 的读取授权由调用方负责。

## 五个任务的实际输出

| 任务 | 输出 | 实现边界 |
|---|---|---|
| roleplay | 角色定义、同角色子知识、既有 memory/anchors/values 导入、指定会话转录 | 提供生成材料，不生成角色回复；不给角色注入未声明属于它的全知资料 |
| world | `ent:` / `cat:` 与 `spatial.coords3d` / `state_attributes` 的实体现值 | 同名实体按已声明观测时间窗及 id 确定性取最新；仅当前候选集，不代表完整世界 |
| story | 按时序/因果边排列的素材提纲、依赖 id 与静态设定背景 | 角色规则/价值/记忆不自动变成剧情事件；相关边不充当因果；循环留缺口；不补写正文 |
| history | 现实来源证据线与待核材料 | 完全排除角色/子知识；有引用仍不自动证明史实；排序是**观测时间窗，不是历史事件年代** |
| causal | 保留每条边条件与来源的有界候选路径 | 不合并平行边，不把相关性改成因果；未验证、推断或资格未定者为 hypothesis |

`history` 的引用沿用 provenance 的 `vref:`，不增加第二套来源字段权威。
`facts` 保留四栏条件、来源声明、引用、节点资格和脑端正文分页元数据。
节点快照与每次返回值均复制，调用方修改输出不会改变其他视图或本地图。
角色与现实之间的边不进入推演；结果按实际可见材料标明 `domain` 和 `domains`，
混合域为 mixed，历史消费恒为 real。故事提纲项另附 domain；混合素材的 fiction 为 null。
脑端现有状态槽按实体名记录，尚无角色命名空间；本件只将这些槽投影到现实实体，
角色同名实体不会继承宿主状态。缺状态返回 null 并留缺口，3D 模型的 neutral 仅是呈现占位。
现实与角色同时声明同名实体时不相互覆盖：排除该歧义实体并返回缺口，保留原材料待核。

## 资格与完整性纪律

- 脑端 `REJECT` 不进入材料；其余资格保留，不提升为 ACCEPT。
- 本地 store 没有脑端资格裁决，节点保留 `BLINDSPOT`，可作为明确待核的材料消费。
- 总结果有材料但存在资格待定、缺条件、截断或预算缺口时为 `DEFER`；无可见材料为 `BLINDSPOT`。
- 因果端点在已有快照中但被作用域排除时为 `REJECT`；端点不存在时为 `BLINDSPOT`。
- 不解释自由文本条件，不替代 COND-ANALYSIS；`ACCEPT` 只说明当前材料组装检查通过，**不证明新事实**。
- 未指定角色/会话时不猜测作用域；多角色/多会话声明有歧义的记录不进入单作用域视图。
- 达到召回上限、正文被剪裁、选取 id 不存在或边数超限都显式留缺口。
- 缺来源声明不改变脑端节点资格，但在组装结果中留缺口；正文截断/节点缺条件仍使因果路径为 hypothesis。
- 多个 ent: 名称不静默映射到首个实体，保留原记录并返回歧义缺口。

因果默认预算：16 条边深度、32 条路径、4096 次栈展开；可显式调整为正整数。
节点默认最多 256 条（超额拒绝），边最多 1024 条（截断留缺口）。
预算限制本层候选/推演；底层 `get_outgoing_edges` 仍可能一次读取该节点全部出边，
不承诺将既有 store 的 SQL I/O 改为有界读取。

## 留给项目确认的设计点

1. 场景消费入口是否归属 `lingshu.world.scenario`，是否采用此 API 命名。
2. 角色对未声明归属于其视角的现实资料默认不可见；是否需要额外的明确授权观察规则。
3. 本地无资格裁决时仅交付待核材料，不依标签“verified”自行升格；是否接入现有白箱判定器。
4. 后续正文生成/历史年代抽取必须新增可追溯候选与验证，不在此消费件冒充完成。

本件没有前端变动、自动写入/升格、默认调用链替换或插件安装方案。
