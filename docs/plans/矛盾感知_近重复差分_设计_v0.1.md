# 矛盾感知——M5 近重复先做极性 / 数值 / 反义差分（v0.1，Refs #142）

> 状态：提案（默认关闭，`LINGSHU_CONTRADICTION=1` 开启）。新增 `lingshu/core/contradiction.py`，core.py 两处挂钩。

## 1. 问题（#142）
M5 去重只看字符二元组 Jaccard ≥ 阈值（静态 0.85，动态 0.85–0.95）。一条长句里插入一个「不」、
把「7.5」改成「75」、把「在线」改成「离线」，Jaccard 几乎不变 ⇒ 更正被当作重复吞掉，原命题 +0.02 增信。
二元组集合本身看不见语义翻转，调阈值解决不了。

## 2. 做法（白箱 · 确定性 · 零 LLM）
只在**已被判为近重复**的一对文本上做 `difflib` 字符级对齐，检查差异片段：
- 极性：一侧差异片段含否定标记（不/没/未/无/非/别/勿/莫/否/并非/尚未…，英文 not/no/never…）而另一侧没有；
  整词落在片段内的非否定常用词豁免（非常、无论、未来、不过，、没错、不错…）；
- 数值：两侧数字多重集不同（阿拉伯数字含小数；连续中文数字）；
- 反义：差异片段两侧 ±3 字窗口命中小反义表（已/未、在线/离线、允许/禁止、通过/否决…），且该词只出现在一侧。

命中 ⇒ **不合并、不增信**；新建节点，并走**既有**的 `register_conflict` 通道（OPPOSITE 边、未验证、置信度 0.3、
`conflict` 标签，等验证单元复核——此前这个通道没有任何自动调用方），另加 `conflict:<原因>` 标签。
`recall` 在开关开时把矛盾对侧紧随宿主插入（矛盾对不拆开，极端情况下结果可略超 limit），其余节点次序不变。

## 3. 实测
构造集：6 类事实模板 × 30（共 180），每条写 1 次后写其更正 5 次；recall(limit=5) 看两侧是否同时出现。

| 指标 | 关 | 开 |
|---|---|---|
| 更正保留为独立节点 | 65.0% | **100%** |
| 其中：数值更正 | 15/60 | **60/60** |
| 其中：反义更正 | 12/30 | **30/30** |
| 其中：极性更正（这批句子 Jaccard 本就 <0.85，原路径也不吞） | 90/90 | 90/90 |
| 原命题被更正「增信」 | 59.4% | 17.8% |
| 矛盾两侧同时召回 | 65.0% | **95.0%** |
| 同义复述（标点 / 语气词 / 豁免词互换，540 对）误判冲突 | 0 | 0 |

真实语料误报（只看 M5 会合并的 Jaccard≥0.85 近重复对）：
- hive-memory-bench 全书块、locomo-zh-567：0 个近重复对（无从误报）；
- KdConv 前 2 万句：44 对，初版误报 2（「没错，…」），据此把「没错 / 不错 / 没关系…」加入豁免表 → 0；
- **KdConv 后 3.1 万句（豁免表定稿后未再看过的留出集）：384 对，误报 4（1.0%）**：3 对是「不算贵，…」前缀
  （多了一个带否定的评价分句），1 对是被截断长句里的数字差异。不再针对留出集调参。

如实说明：
- 「原命题被更正增信」开启后仍有 17.8%：不是更正，而是**不同实体**的事实（只差人名 2–3 字）被 M5 合并——
  M5 对实体不敏感，属另一问题，本提案不碰。
- 两侧召回 95% 而非 100%：剩下 5% 是原检索路径根本没把任一侧取进前 5（#35）；接 FTS5 路径后见集成读数。
- 构造集的更正都是单点改写；真实更正常伴随整句重写（Jaccard 低于阈值，本来就不会被合并），本机制不覆盖那类
  「换了说法的矛盾」——那需要语义层，不在白箱范围内。
