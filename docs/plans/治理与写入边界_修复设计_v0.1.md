### 1.2 边界①（硬）：`#140` 的窗口**不能**靠修 `#118`/`#127` 消掉

已实证（独立复核 `probe_cross`）：在副本里**先证**「`#127` 模拟修复」与「`#118` 模拟修复」各自生效，再跑 `#140` ⇒ **窗口仍在**。

原因（两条正交）：
1. `#140` 的换内容发生在**知识层**节点上（旧行非共享层 ⇒ `#127` 的「查旧行 layer」修复**放行**）；
2. 换内容时流水线状态与三方身份**全程合法**（⇒ `#118` 的角色/状态机修复**放行**）。

⇒ **`#140` 需要独立改动**：提案在提交时**绑定被复核内容的快照/版本**，复核与终裁时**重算比对**。
`#118`/`#127` 的修复合集是 `#140` 的**必要条件之外的独立项**，不得合并抵扣。
（唯一部分重叠：若把修复做成「提案 `pending`/`verified` 期间拒绝同 id 覆盖」，则**顺带**堵 `#127` 的降级侧门——但那是 `#140` 建议 3 的取法，且仍**不**取代 `#127` 自身修复。）

### 1.3 边界②（硬）：**不得**把「策略选择」当成「缺陷修复」

下列各项**是取舍、不是缺陷**，其取值**必须由设计者拍板**，不得由实施者以「修 bug」名义默认选定（详见 §2–§7 各自的「策略选择点」，汇总见 §12）：

- 修在**哪一层**（应用层判据 vs DB 触发器/约束）——仓内**零 `CREATE TRIGGER`**，且结构对照 `_SCHEMA_TABLES`/`_SCHEMA_COLUMNS`/`SCHEMA_VERSION` 需同步。
- 判据的**方向/严格度**（如 `#130` 的匹配方向、`#118` 的身份互斥范围）。
- **不一致时的处置语义**（`#140`：作废 / 拒终裁 / 重开复核）。
- 是否**扩大作用域**（`#109`：只在外部锚点入口加闸 vs 连 `set_anchor`/`add_structure_node` 一并收口）。
- **私有侧兼容口径**（`#125`：拒绝 vs 需密钥放行）。

凡属上列者，本稿**给推荐、不擅自定**；实施只做「把**已有**闸补到漏掉的路」这一**无分歧**部分。

## 2. `#127` 同 id 降级绕过共享层写保护（只设计）

**判定**：成立（单一 `PRIMARY` 实例亦可复现，与角色无关）。

**根因锚（符号锚）**
- `LayeredStore.add_node`：关键语句 `if node.layer in self.IMMUTABLE_LAYERS and self.role != Role.PRIMARY:`，随后
  `INSERT OR REPLACE INTO nodes`。判据**只看「待写节点」的 layer，不看库内同 id 旧行的 layer** ⇒ 旧结构层行被整行替换为知识层（降级）。
- `LayeredStore.delete_node`：保护依据是**当前行的 layer**（已被上一步改掉）⇒ 放行。
- `LayeredStore.update_node_confidence` / `update_node_importance`：两条 `UPDATE` **无任何 layer/角色判断**。

**修法形状（推荐基线）**
1. `add_node`：写入前查同 id 旧行；旧行 ∈ `IMMUTABLE_LAYERS` 时，非 `PRIMARY` 一律 `PermissionError`；且**禁止**把共享层旧行改写成其它层（降级）。
2. `delete_node`：判据升级为「当前行 layer ＋ 角色」双重校验（防御纵深）。
3. `update_node_confidence/importance`：加同款 layer/角色守卫，或对共享层直接拒绝下调。

**策略选择点**
| # | 选择 | 选法 | 代价 | 推荐 |
|---|---|---|---|---|
| S-127-1 | 覆盖原语的修法 | (a) 写前查旧行 layer（最小） / (b) 共享层改显式 `INSERT` + 冲突报错，替掉 `INSERT OR REPLACE` / (c) DB 触发器 | (a) 最小、不动 schema / (b) 更彻底但改共享层写入路径，波及同步逻辑 / (c) 需新增 `CREATE TRIGGER`（仓内零先例）+ 升 `SCHEMA_VERSION` | **(a)**，并以 `#127` 的 [C2] 单实例读数钉住 |
| S-127-2 | `PRIMARY` 自身降级是否也禁 | (a) 只拦非 `PRIMARY`（保留「父节点主控」语义） / (b) 连 `PRIMARY` 也禁改 layer，改层走显式迁移接口 | (a) 留「父节点自己降级」缺口 / (b) 更严，需定义迁移接口 | **(b)**（[C2] 已证单 `PRIMARY` 同样被绕） |
| S-127-3 | 数值接口是否同批 | (a) 共享层拒绝下调 / (b) 全层加守卫 | 属**独立缺口**，是否同批由设计者定 | **(a)**，或另立件 |

**守卫判据**
- `add_node(同 id, layer=knowledge)` 作用于结构层旧行 ⇒ `PermissionError`，且旧行内容/层**不变**。
- `update_node_confidence/importance(共享层, <0)` ⇒ 拒绝或值不变。
- 防误杀：新建（无同 id 旧行）写共享层、非降级覆盖，照旧通过。

**受影响的既有测试**
- `tests/test_layer_enumeration.py`（用例 `test_engine_returns_entire_anchor_collection` 经 `set_anchor`、`add_nodes(...ANCHOR/STRUCTURE...)` 经 `LayeredStore.add_node`）：均用**全新 id**、默认 `PRIMARY` ⇒ **无同 id 冲突**，`#127` 的「查旧行」修复**不触发** ⇒ 预期**仍绿**（须实跑确认）。
- `tests/test_core_foreign_key_enforcement.py`：不涉覆盖原语，预期不受影响。
- **无**既有测试把「同 id 降级」锁成期望行为；`#127` 的守卫属**新增**（报告 §6 已列缺口）。

## 3. `#140` 复核内容在终裁前可被调换（只设计）

**判定**：成立（三方身份两两不同、不依赖 `#118`）。

**根因锚（符号锚）**
- `promotion_proposals` 建表块（唯一特征串 `id TEXT PRIMARY KEY, node_id TEXT, requester TEXT, reason TEXT,`）：
  **只有 `node_id`，无内容快照 / `content_hash` / 版本列** ⇒ 提案记的是**指针**。
- `LayeredStore.adjudicate_promotion`：`UPDATE nodes SET layer='structure', confidence=1.0 WHERE id=?`——按 id **就地改层**，批准的是**当下**该 id 的内容。
- 换内容原语 = `#127` 同一原语 `LayeredStore.add_node` 的 `INSERT OR REPLACE`（此时旧行为知识层，`#127` 的层检查本就不覆盖）。

**修法形状**
1. `promotion_proposals` 加 `content_hash`（或 `content_snapshot`）+ 版本列（**须同步升 `SCHEMA_VERSION`**，并进 `_SCHEMA_COLUMNS`）。
2. `add_promotion_proposal` 落快照；`verify_promotion` / `adjudicate_promotion` 时**重算比对**，不一致按选定策略处置。
3. 或（更彻底）终裁时**从快照新建**结构层节点，而非就地改层。

**策略选择点**
| # | 选择 | 选法 | 代价 | 推荐 |
|---|---|---|---|---|
| S-140-1 | 绑定机制 | (a) `content_hash` 列（复用 `cond_hash` 口径） / (b) `content_snapshot` 全量列 / (c) 终裁从快照新建节点 | (a) 省空间、需规范化口径一致 / (b) 冗余但可回放 / (c) 改终裁写入路径 | **(a)**，配 §1.3 判据 |
| S-140-2 | 不一致时处置 | 作废提案 / 拒绝终裁 / 回退到复核态 | **纯策略** | **拒绝终裁 + 提案作废**（须设计者确认） |
| S-140-3 | schema 迁移 | 加列即升 `SCHEMA_VERSION` 并补 `_SCHEMA_COLUMNS` | 老库启动只读化守卫据此补列 | **必须**（既有机制约束，非可选） |

**守卫判据**
- `propose(content=A) → verify → add_node(同 id, content=B) → adjudicate(True)` ⇒ **终裁被拒**，节点留 `knowledge`，`content` 仍为 A。
- 未改写时正常通过（防误杀）。
- 断言**必须**与「`#118` 修复已生效」**同时成立**（证其独立，§1.2）。

**受影响的既有测试**
- `tests/test_core_legacy_schema_migration.py`：其结构对照基于 `_SCHEMA_TABLES`/`_SCHEMA_COLUMNS`/`SCHEMA_VERSION`。**新增列必须同步这三处**，否则该守卫对「版本匹配但结构陈旧」的库判据会漂；该件本身**不改断言**，但**新增的列名须进对照**。
- 其余：无（治理流水线在 `tests/` 下**零行为覆盖**，见报告 §6）。

## 4. `#118` 审批角色与状态机缺约束（只设计）

**判定**：成立（分项）。缺状态机的是 **D-003 层晋升流水线**；A-2 验证标准流水线**状态门齐全**，缺**身份互斥**与**值域/参数白名单**。

**根因锚（符号锚）**
- `LayeredStore.verify_promotion`：`UPDATE promotion_proposals SET verified_by=?, status='verified' WHERE id=?`——**无条件 UPDATE，无前置状态门** ⇒ 可把 `rejected`/`approved` 拉回复核态（终态可重开）。
- `LayeredStore.adjudicate_promotion`：`if status != "verified": return None`——**只查入态、不冻结出态**。
- 对比先例：`review_verifier_standard` / `cs_review_verifier_standard` / `adjudicate_verifier_standard` 有 `pending/reviewed/cs_approved` 三段式门，D-003 **一段都没有**。
- 身份不互斥：`requester`/`verified_by`/`adjudicated_by`、`proposer`/`independent_reviewer`/`cs_reviewer`/`adjudicator` 均自由文本，**无相等性判断**。
- 终裁值域：`SpacetimeMemoryEngine.adjudicate_verifier_standard` 原样写值（`self._dedup_static = result["value"]`），而公开入口 `set_dedup_config` **有钳制** ⇒ 最严格路径反而无钳制。

**修法形状**
1. `verify_promotion`：加 `WHERE status='pending'`（或先查状态）+ 校 `rowcount` + 拒绝 `verified_by == requester`。
2. `adjudicate_promotion`：终态冻结（`approved`/`rejected` 不可再转换）；`UPDATE` 校 `rowcount`。
3. A-2 三条：加身份互斥（reviewer≠proposer 等）。
4. `adjudicate_verifier_standard`：应用时**复用** `set_dedup_config` 的钳制（或 `dedup_static` 走该公开入口）；`propose_verifier_standard` 阶段加 `param` 白名单。
5. 终裁记录**只追加**（独立审计行），不覆盖旧值。

**策略选择点**
| # | 选择 | 选法 | 代价 | 推荐 |
|---|---|---|---|---|
| S-118-1 | 身份互斥范围 | 强制 `verified_by != requester`；终裁人是否允许与复核人同身 | 属口径决定，须落成代码断言 | **强制 requester≠verified_by**；终裁人互斥**待设计者定** |
| S-118-2 | 终态冻结语义 | (a) 永久冻结 / (b) 允许「撤回后**新建**提案重提」 | (a) 最简 / (b) 需撤回接口 | **(b)** 语义（原地不可重开，重提走新提案） |
| S-118-3 | 值域归属 | (a) 终裁应用复用 `set_dedup_config` 钳制 / (b) 在 propose 阶段就拒越界值 | (a) 最小 / (b) 更早失败 | **(a)+(b)** 组合 |
| S-118-4 | `param` 白名单来源 | 由既有配置键集派生 vs 显式常量表 | 需定义权威源 | 设计者定 |

**守卫判据**（报告 §6 已列，逐条钉）
- 终态不可重开：`propose→verify→adjudicate(False)` 后再 `verify(同 id)` ⇒ 状态**仍 `rejected`**；`approved` 后再 `verify`/`adjudicate` 不改状态。
- 身份互斥：`verify_promotion(verified_by == requester)` ⇒ 拒。
- 值域：`adjudicate dedup_static=0.1` ⇒ 钳制到 `0.5`（或在 propose 即拒）。

**受影响的既有测试**：无（治理流水线零行为覆盖）。新增断言属**补缺口**。

## 5. `#109` 外部锚点直接进入结构层（**已实施**，设计如下）

**判定**：成立（默认 `role=PRIMARY` 即可，无需任何密钥）。

**根因锚（符号锚）**
- `SpacetimeMemoryEngine.register_external_anchor`：`PRIMARY` 分支 `return self.add_structure_node(...)`。
- `SpacetimeMemoryEngine.add_structure_node`：构造 `confidence=1.0, layer=MemoryLayer.STRUCTURE`，**无密钥形参、无闸**。
- `LayeredStore.add_node`：唯一共享层写判据只判「角色是否 `PRIMARY`」，而 `Role.PRIMARY` 是 `__init__` 默认 ⇒ 默认构造即满足。
- 对照真闸：`LayeredStore.adjudicate_promotion`（同为「写结构层」）**无密钥即 fail-closed**。

**修法形状**：给 `register_external_anchor` 加 `designer_key: str = None` + `verify_designer` 闸（与 `adjudicate_promotion` **同款**，顶部无条件、fail-closed、抛 `PermissionError`），**不做**「降级到知识层」的静默放行。

**策略选择点**
| # | 选择 | 选法 | 代价 | 推荐 |
|---|---|---|---|---|
| S-109-1 | 闸的作用域 | (a) **整个 `register_external_anchor` 入口** / (b) 仅 `PRIMARY`（写结构层）分支 | (a) 连 `SUB` 写知识层的路径也需密钥（知识层写本无密钥先例，属**扩面**）/ (b) 更窄，只收口「写入不可遗忘层」的危害面 | 本稿采 **(a)**（对齐 `adjudicate_promotion` 的顶部落点与「无密钥即拒」的字面口径）；若设计者认为 `SUB` 知识层写不应被收口，切 **(b)** |
| S-109-2 | 是否一并收口 `add_structure_node` / `set_anchor` | (a) 只在外部锚点入口加闸 / (b) 连 `add_structure_node`/`set_anchor` 一并「需 `verify_designer`」 | (b) 会**变更** `tests/test_layer_enumeration.py::test_engine_returns_entire_anchor_collection`（它**无密钥直接调 `engine.set_anchor(...)`**）；且属**扩大**授权面 | 本次采 **(a)**（最小、无政策分歧）；(b) 单列为待拍板项 |

**守卫判据**：无密钥/未配置 ⇒ `PermissionError` 且**零落库**；错误密钥 ⇒ 同拒；正确密钥 ⇒ 照旧写 `STRUCTURE`/`confidence=1.0`；拒绝形态是 `PermissionError` 而非静默降级。

**受影响的既有测试**
- `tests/test_layer_enumeration.py::test_engine_returns_entire_anchor_collection`：**主动依赖**「无密钥 `set_anchor` 可用」。按 **S-109-2=(a)**，本件**不**收口 `set_anchor`/`add_structure_node` ⇒ 该用例**不受影响、预期仍绿**（已实跑确认，见 §10.3）。
  **若**设计者选 **(b)**（一并收口），则该断言锁的是「无密钥即可写不可遗忘层」这一**缺陷行为**，届时更新口径为：用例改为「以正确密钥调用」或「改走 `LayeredStore.add_node` 直造锚点」——**逐条理由**须在实施时写明，且**不得**为过测试而放宽新闸。
- 无其它既有测试引用 `register_external_anchor`（全仓 grep 仅定义处）。

## 6. `#125` 备份恢复绕过写入边界（只设计）

**判定**：成立（① 恢复路径无授权覆盖结构层；② SQL 列名未参数化直接拼接）。

**根因锚（符号锚）**
- `SpacetimeMemoryEngine.import_all`：`cols = list(rows[0].keys())` / `col_sql = ",".join(cols)` / `c.execute(f"INSERT OR REPLACE INTO {table} ({col_sql}) VALUES ({placeholders})", ...)`。
  - `table` 取自固定清单 `M13_TABLES`（不可控，非注入面）；`cols` 取自**备份 JSON 的键逐字**，经 f-string 拼进 SQL ⇒ 列名未参数化（SQLite 标识符本不可绑定参数，正确修法是**白名单过滤**）。
  - `import_all` **绕过 `LayeredStore.add_node`**（直接 `self.store.conn` 执行 `INSERT OR REPLACE`）⇒ `add_node` 的角色闸、`adjudicate_promotion` 的密钥闸**全被跳过**；以 `nodes.id`（`TEXT PRIMARY KEY`）覆盖既有结构层行的 `content`/`confidence`。
- 事后体检（**不拦写入**）：`import_all` 末尾 `PRAGMA foreign_key_check` 注释原文 `恢复了损坏备份这件事随返回值交付（不拦写入）`。

**修法形状**
1. 列名：用 `PRAGMA table_info(<table>)`（或既有 `_existing_tables()` 同款「以库内事实为准」思路）取真实列集，与备份行键**求交集**后再拼 SQL；非白名单键丢弃并计数上报。
2. 授权/层边界：对将覆盖的行做**层判定**——命中 `IMMUTABLE_LAYERS` 时要求 `verify_designer(designer_key)`（`import_all` 新增 `designer_key` 形参），或直接拒绝。
3. 可选加固：连接 `PRAGMA foreign_keys=ON`（**独立动作**，且**不等于**授权）。

**策略选择点**
| # | 选择 | 选法 | 代价 | 推荐 |
|---|---|---|---|---|
| S-125-1 | 不可变层覆盖处置 | (a) 直接**拒绝** / (b) 需 `designer_key` **放行** | (a) 灾备恢复不可恢复共享层 / (b) 保留恢复能力、需私有侧补配置 | **(b)**（灾备语义需要；配 §9 迁移） |
| S-125-2 | 列名白名单来源 | `PRAGMA table_info` vs 复用 `_existing_tables` 同款思路 | 前者更贴库内事实 | **`PRAGMA table_info`** |
| S-125-3 | 非法键处置 | 丢弃并计数 vs 抛错 | 抛错更严、可能破坏既有降级口径 | **丢弃 + 上报计数** |

**守卫判据**
- 篡改备份 `structure` 行 ⇒ 无密钥 `import_all` **拒**（或该行不覆盖）。
- 传非法列名 ⇒ 被**丢弃**而非拼进 SQL。
- `SUB`/无密钥恢复共享层 ⇒ 拒。
- 防误杀：知识层往返照旧通过。

**受影响的既有测试**
- `tests/test_core_foreign_key_enforcement.py::test_import_of_dangling_reference_is_reported`：断言原文 `ret["imported"]["edges"] == 1, "对照：边仍落库（不改写入行为）"`。**该断言把「不拦写」锁成期望行为**——但其入参是**知识层节点**（`_node(...)` layer=`knowledge`）⇒ 按 **S-125-1=(b)**（只对**不可变层**行加闸）时该断言**仍成立、无需改**。
  **若**设计者选「拒绝整次导入」，则该断言锁的是缺陷行为，须**有理由地**更新为「边仍落库」→「共享层行被拒、普通行照旧落库」。**理由**：`#113` 的可见判据只报告不拦写，与治理诉求相反（报告 §6 原话）。
- `tests/test_core_export_all.py`（脚本式，#16 守卫）：B 组往返用 `add_perception`（知识层）⇒ 按 S-125-1=(b) **不受影响**。
- 列名一条属**加固**，无既有断言锁定「拼接」行为。
