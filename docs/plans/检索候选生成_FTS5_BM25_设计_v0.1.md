# 检索候选生成：FTS5 字符二元组 + BM25（设计 v0.1，默认关闭）

Refs #35（`search_content` 无 ORDER BY，`LIMIT 300/500` 按插入顺序截断）

## 1. 问题：瓶颈在候选生成，不在打分

`LayeredStore.search_content` 现行三步：

1. 同义词扩展 → `content LIKE '%t%' OR tags LIKE '%t%'` 预筛，`LIMIT 300`，无 ORDER BY；
2. 预筛落空 → 回退 `SELECT * FROM nodes LIMIT 500`（同样无序）；
3. 对候选算原查询的二元组 Jaccard 排序。

自然语言问句、带空格的关键词串几乎不会作为连续子串出现在原文里，于是大量查询走第 2 步：
**库一过 500 条，后写入的记忆对这类查询永久不可达**，结果只取决于插入顺序。
单加 `ORDER BY`（#35 的直接修法）能让截断变得确定，但仍只在前 300/500 行里找，不解决可达性。

诊断读数（同一批查询）：对全表逐条算 Jaccard，命中率与 BM25 接近，但 2 万条时单次 393 ms。
所以收益来自「从全库按相关度取候选」，不来自换一个打分公式。

## 2. 方案

新增 `lingshu/core/retrieval.py`，`core.py` 只在 `LayeredStore.__init__` 和 `search_content`
各挂一个分支（约 50 行）。

- **索引**：FTS5 普通表 `nodes_fts(toks)`，文档是节点 `content + tags` 折叠空白后，在汉字或字母数字连续段内取字符二元组（单字段保留单字），用空格分隔，交给 `unicode61` 切词。分词口径与 `char_bigram_jaccard` 一致（同样先折叠空白）。全确定、可溯源、零新依赖（标准库 sqlite3 自带 FTS5），符合 D-005。
- **同步**：触发器只把变更节点的 id 写进脏队列 `nodes_fts_dirty`。这是纯 SQL，任何连接、任何写入路径都会入队，包括绕过 `add_node` 的裸 SQL。检索前由 Python 增量排空。不在触发器里切词，因为那要求每条连接都注册 Python 函数。
- **rowid 漂移**：`INSERT OR REPLACE` 会换 rowid，所以通过 `nodes_fts_map(nid → frid, hash)` 按 id 关联。内容哈希不变的覆盖写（比如只改置信度）跳过重建。
- **老库**：开关首次打开时，把映射表里没有的节点全量入队并排空（5 万条约 1.5 s，只发生一次）。
- **查询**：原查询加同义词扩展词的二元组 OR 起来（最多 256 项，防 #266 那类超长查询），先在 FTS 内 `ORDER BY rank LIMIT k`（k = max(5·limit, 100)），再回表。先截断再回表很关键：先 JOIN 再排序会让高频二元组的全部命中行回表，5 万条时退化到秒级（实测 p95 9 s，已修）。有层过滤时内层放大 4 倍，不足再按 4 倍逐级放大。
- **逐字命中优先**：逐字包含查询原文（content 或 tag）的节点排在最前，与原 LIKE 主命中语义一致；剩余名额按 BM25 部分匹配补足。（v0.1 初稿曾让逐字命中排他，但这与上游 #44 冲突：`longterm_snapshot`/`prefeed` 要在逐字命中的新节点之外找到相似旧节点来建 similar 边。改为不排他后，hmb 与 locomo 读数不变。）
- **打分契约**：调用方有阈值，`longterm_gate` 用 `>=0.95` 判重、`>=0.25` 建 similar 边，所以返回分数为

  `score = max(Jaccard + tag 加成, 0.9 · s / (s + 10))`，s 为 BM25 正分。

  BM25 分量封顶 0.9，所以 ≥0.95 只可能来自 Jaccard，「包含查询的长文」不会被判成重复。排序则主要由 BM25 决定：IDF 压低「什么」「为什」这类高频二元组，长度归一化也温和。K=10 和 0.9 是事先选定的，**没有在任何评测集上调过**。
- **回退**：编译时不带 FTS5、库只读、任何 `sqlite3.Error` 都返回 None，交回原路径。
- **开关**：`LINGSHU_FTS=1` 打开，默认关闭。关闭时如果库里残留本模块的触发器，启动时就拆掉并清空派生表，下次打开时全量重建。保证默认写路径与改前一致。

## 4. 失败项与边界（如实）

- **「另一侧覆盖」没有稳定提升**（A 3→5/40，B 4→4/56，B 全书 4→3/56），属于噪声量级。要覆盖矛盾的另一侧，需要极性和否定感知，不在本 PR 范围。
- 自然语言问句加上大规模异领域干扰时，FTS 也会明显下降（5 万条时块级命中 17.3%）。问句里的高频二元组仍然会稀释排序，本方案只解决可达性，不解决这一点。
- 5 万条时 p50 比原路径慢约 5–9 ms（原路径快是因为只扫前 500 行，命中率 3%）。
- 跨领域干扰（KdConv）比真实使用容易；locomo 的查询是由金标派生的关键词串，读数偏乐观。
- 我们还试过白箱实体桥接：在切 A 上调参后有提升，到留出的切 B 上反而退化（证据保留 27.2%→23.8%），判为过拟合，**不纳入**。向量 / embedding 路径因 D-005 也不纳入。
- 开关打开后，`test_core_search_discrimination::test_document_without_query_scores_zero` 的前提不再成立：该用例依赖回退路径把零重叠文档以 0 分返回，FTS 路径下这类文档直接不返回（更严格）。默认关闭时该用例照常通过。
