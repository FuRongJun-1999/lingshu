## 1. 数据：`evidence` 表（新增，不改旧表）

| 列 | 含义 |
|---|---|
| `node_id` | 被支持/反驳的节点 |
| `source` | 来源（规范化：去首尾空白、小写；空 → `unattributed`） |
| `polarity` | `1` 支持 / `-1` 反驳 |
| `weight` | `(0, 1]` 且有限；NaN / inf / 越界 **拒绝**（不静默钳位，对照 `#185` `#402`） |
| `self_generated` | 系统自产（反思、自评、推断）＝ 1 |
| `note` / `created_at` | 备注 / 时间 |

`CREATE TABLE IF NOT EXISTS`，只在启用时建；未启用的库不多一张表。

## 2. 推导（白箱，阈值显式）

```
S = Σ_{独立来源 s} max(该来源的支持权重)      （self_generated 不计）
C = Σ_{独立来源 s} max(该来源的反驳权重)
confidence = (1 + S) / (2 + S + C)            # Beta(1,1) 先验的后验均值
```

- 无证据 = 0.5；单一来源满权支持 = 0.667；两个独立来源 = 0.75；一支一反 = 0.5。
- **永远到不了 1.0**：1.0 只能来自本项目的终裁路径（`adjudicate_promotion`，本稿不动）。

状态：`unverified`（无计分支持）/ `single_source` / `corroborated`（≥ `CORROBORATION_MIN`=2 个独立来源、无反驳）/ `contested`（支持与反驳并存）/ `refuted`（只有反驳）。

推导值经 `sync()` 写回 `nodes.confidence`——**既有读路径（衰减、排序、导出）看到的是同一个值**，不出现两套置信度。

## 4. 边界（修不完的显式标出）

1. **不做语义矛盾判定**：`#142` 的「不过敏」被并进「过敏」是 M5 匹配器的极性/数值盲区，本稿不碰。本稿保证的是：一旦反证被记进来，置信度会降，且不会被重复写入「养」回去。
2. **来源独立性靠调用方声明**：本稿只规范化 `source` 字符串，不核验身份。同一个人换两个 source 名仍能伪造「佐证」——这需要上游的来源绑定（`provenance`）接入，列为后续。
3. **未改的入口**：`update_node_confidence`、`verify_edge`、`insight_verify`、技能置信度（`update_skill_confidence`）仍是旧语义。逐个迁移属于设计取舍，待裁后另开 PR，**单件单 PR**。
4. **`recall()` 终排未改**：仍不看置信度；只在 `recall_with_evidence()` 里附评估、剔除已反驳。是否把置信度纳入终排待裁。
