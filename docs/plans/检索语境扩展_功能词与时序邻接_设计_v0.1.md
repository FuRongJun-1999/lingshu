# 检索语境扩展：问句功能词过滤 + 时序邻接平滑 · 设计 v0.1

状态：提案（默认关闭）。开关：`LINGSHU_FTS=1` 且 `LINGSHU_FTS_CONTEXT=1`。依赖 FTS5 检索 PR（Refs #35）。

## 1. 问题
FTS5+BM25 解决了「候选生成」之后，hive-memory-bench 切B 的证据保留只有 24.4%。把漏掉的证据逐条拆开（自建口径，切A 301 条 / 切B 467 条）：

| 漏检原因 | 切A | 切B |
|---|---:|---:|
| 证据块与问句**零共享二元组**（分析题、动机题） | 111 | 159 |
| 有共享但排在 10–100 名 | 112 | 167 |
| 漏检块就在 top-10 某块的前/后一段 | 45 | 61 |

两个可白箱处理的成因：
1. **问句模板词**：「请说明」「这部作品」「哪些」「人物」「身份」等在每道题出现，也散落在叙述里，BM25 会给它们分，把只含模板词的噪声块顶上来。
2. **证据常在命中段落的邻居里**：对话的下一句、叙述的下一段与问句没有字面重叠，但与命中段落同属一个语境。

## 2. 机制
- `retrieval.QUERY_FUNCTION_GRAMS`：手写的通用问句/指令二元组表（约 130 个），只作用于查询侧；全部被滤掉时保留原查询。
- `FTSIndex.temporal_neighbors`：按 `temporal_coordinate` 取每个种子的前一条与后一条（同层过滤），间隔超过 `NEIGHBOR_WINDOW_S=3600` 秒视为会话边界。为此新建索引 `idx_nodes_fts_tc`（派生结构，与 FTS 表同属检索开关）。
- `_fts_context_smooth`：BM25 前 `NEIGHBOR_SEEDS=30` 个候选作为种子，邻居得分 = 自身 BM25 + `γ·max(种子 BM25)`，`γ=NEIGHBOR_GAMMA=0.2`；随后与原路径一样，与 Jaccard 取 max 后再截断。
- **只在自然语言路径生效**：候选中存在逐字包含查询的节点时，不做平滑，逐字闸门语义不变。

## 3. 参数选择
只在切A 上选：γ∈{0,0.2,0.4}，A 上 0.2 最好（31.6）。切B、全书切B、加干扰的切B、locomo 都是留出集。功能词表手写，不看语料统计；但写表时看过切A 的部分题面，**存在偏向本基准题型的风险**。敏感性检查（自建 harness，同一组 BM25/邻接参数）：切B 全表 33.2，不用表 29.8，随机抽一半词条重复 20 次为 29.3–31.7。即一半的增益不依赖表里具体是哪些词。

## 4. 实测（真实引擎 `store.search_content` top-10，顺序写入）
| 套件 | FTS | FTS+语境扩展 |
|---|---|---|
| hmb 切A（调参集）证据保留 / 块级命中 | 25.9 / 80.7 | 31.6 / 79.1 |
| hmb 切B（留出）| 24.4 / 69.6 | **29.6 / 72.2** |
| hmb 切B + 全书 23 章同领域干扰 | 21.0 / 60.8 | 25.5 / 64.5 |
| hmb 切B + 1 万条 KdConv 跨领域干扰 | 7.3 / 27.8 | 10.3 / 33.2 |
| locomo-zh 1 万干扰 hit@10 / MRR | 1.00 / 0.965 | 1.00 / 0.970 |
| p50 延迟（切B） | 7.7 ms | 10.6 ms |

消融（切B）：只做功能词过滤为 28.3；γ=0.2 时 29.6；γ=0.4 时 30.4，但块级命中掉到 67.5。乱序写入时邻接不再对应语境，结果为 28.5，与只做功能词过滤（28.3）基本相同。

## 5. 不解决的
- 「另一侧覆盖」不变（4/56），不要据此宣称多跳/对照证据问题已解决。
- 零共享二元组的分析题（占漏检约三分之一）仍然取不到，需要语义层，不在 D-005 白箱范围内。
- 邻接依赖写入顺序 ≈ 语境顺序；批量乱序导入的库不会受益，但也不会变差（乱序写入实测切B 28.5，FTS 基线 24.4）。
