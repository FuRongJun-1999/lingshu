### 1.2 边界①（硬）：`#93` 启用外键属**改写入语义的策略变更**，不是纯 bug 补齐

本仓既有**权威取向**是「**可见判据（应用层返回/抛错），不靠 DB 级强制**」——见 `docs/plans/治理与写入边界_修复设计_v0.1.md` §1.1 表格「「可见判据」取向」一行，其符号锚正是 `tests/test_core_foreign_key_enforcement.py`。

按此取向，「连接级 `PRAGMA foreign_keys=ON`」**不是**把漏掉的 bug 补上，而是把「`add_edge` 对新孤儿边**永远成功**」改成「**不满足即抛 `IntegrityError`**」——这是**改变对外写入契约**的**策略变更**，其代价面已由 B 端核验实测坐实（§4.3）：

- 波及**全部** `add_edge` 调用点（`register_conflict` / `update_self` / 认知循环 / `subgraph_replace` / 概念建边 / `longterm_gate.py` 两处），凡「先写边、后写点」者由**静默变抛错**；
- 落点是**每连接 PRAGMA**（非 DDL；新裸连接默认 0，仓内连接不止一处）；
- **存量孤儿边不自动清理**（启用前后同为 1）；
- 与 `#69`（缺表**降级不失败**）、`#113`（悬挂**事后报告不拦写**）两条**已合入口径直接冲突**（§6.3）。

⇒ **该件的取舍必须由设计者拍板**；本稿在 §4.4 给推荐，但**不擅自定**。**不得**以「修 bug」名义默认启用。

### 1.3 边界②（硬）：**不得**把「策略选择」当「缺陷修复」

下列各项**是取舍、不是缺陷**，其取值**必须由设计者拍板**，不得由实施者以「修 bug」名义默认选定（逐件见 §2.4／§3.4／§4.4／§5.4，汇总见 §10）：

- **保护的时效性**（永久 vs TTL vs 显式解除）——现状 `protections.created_at` **从不被读**。
- **保护命中的处置语义**（整体拒绝 vs 跳过上报 vs 降级断边）。
- **共享引用的删除语义**（只删专属后代 vs 孤儿化 vs 拒绝）。
- **大子树是否截断**（不截断 vs 截断即拒 vs 分页）。
- **判据落在哪一层**（应用层判据 vs DB 触发器/约束；仓内**零 `CREATE TRIGGER`** 先例）。
- **FIFO 上限与保护的优先序**（保护优先超限 vs 淘汰次旧非保护项 vs 拒写）。
- **保护登记的失效清理**（级联删 vs 过滤悬空 vs 拒删）。
- **原子性实现**（事务边界 vs 预校验＋staging）。
- **保护是否需授权**（谁能 `protect_node`/解保护）。
- **遗忘判定是否收敛为单一谓词**。
- `#93` **约束落点**（应用层可见判据 vs 连接级 DB 强制）、**存量孤儿处置**、**与导入路径共存口径**。
- `#33` **恢复失败处置**（回退默认 vs 拒启动 vs 回退＋显式标注）、**恢复源**、**序列化版本**、**恢复范围**、**`identity` 冲突优先序**。

### 2.3 修法形状（含推荐）

一条路径需同时补 6 道防线；逐条给出「要动哪 ＋ 有无既有机制可复用」：

| 防线 | 要动 | 复用/新增 |
|---|---|---|
| 前置校验 `new_subtree` 必需键 | `_attach` 前递归校验 `id`/`content` 键 | **无直接先例**；样式参考 `LayeredStore.adjudicate_promotion` 的「入口顶部无条件校验」 |
| 校验 `old_sub_root_id` 与 `parent_id` 关系 | 新增父子断言 | 关系读取 `get_outgoing_edges`/`get_incoming_edges`（已有）；**`LayeredStore` 无 `is_descendant` 一类闭包判据**（勿误引），须新写或由 `traverse(direction="in")` 结果集运算得来 |
| 专属后代集合（共享引用只断边） | 对候选后代判「其 hierarchical **出边**是否全在待删集合内」 | `get_outgoing_edges(node_id)`（已有）＋ `traverse` 结果集（已有）；**无专用 helper** |
| 保护/不可变过滤（全有或全无） | 删除前查 `IMMUTABLE_LAYERS` ＋ `get_protected_nodes()` ＋ `no_forget` 标签 | **已有三件先例**（§1.1）；**推荐同时下沉到 `delete_node`**（§6.1） |
| 原子化（删＋建同一事务、异常回滚） | **仓内零先例** | ⇒ 必须**新引入**事务边界（见下） |
| 不截断／截断即拒 | 传 `max_nodes=None`（或足够大），或截断即拒绝 | `LayeredStore.traverse` 的 `max_nodes` 形参（已有） |
| 忠于 `delete_node` 返回、`removed_nodes` 只计实数 | 收集布尔返回；被拒节点另列 | `delete_node -> bool` 契约（已有）；审计可落 `action_logs`（`log_action` 已有） |

**原子性要什么（判定：`#139-A` 是「先删后校验」，要原子化必须引入仓内当前不存在的机制）**

- 现状取证：`grep` `rollback|SAVEPOINT|BEGIN IMMEDIATE|isolation_level` **全仓零命中**（唯一 `rollback` 字样在维生系统指令 docstring，非事务原语）。`store._lock` 是 `threading.Lock`，只管互斥**不管事务**；`delete_node`/`add_node`/`add_perception` **每次自带 `commit()`** ⇒ 逐个删除各自持久化，**异常时无回滚点**。
- ⇒ 要原子化，**必须新引入**以下之一（**无既有可复用件**）：
  1. **事务边界**：`with self.store._lock:` 包裹「删＋建」并抑制中间 `commit()`，异常 `rollback()`；或 SQLite `SAVEPOINT` / `conn` 上下文。
  2. **预校验＋staging**：先在临时区（内存子树或旁路表）**完整构建并校验**新子树，成功后再单次提交式换入——本件 ①②③⑥ 可由此先消，**④⑤ 仍需删点侧判据**。
- **推荐**：**(2)＋(1) 组合**——预校验先行（消 A/B/C、并把「校验失败 ⇒ 零删除」做成默认），事务兜底（消「部分失败」这一剩余窗口）。**仅**「预校验」可消 A/B/C，但**共享引用/保护/计数**仍要改删除侧；**完整原子性必须落到事务边界这一新原语**。
- **明确否定的修法**：**不许**用「把 `PRAGMA foreign_keys=ON` 打开」替代原子性（B 端已实测：FK 强制会**连坐** `delete_node`/`decay_cycle`/`subgraph_replace` 三条路径抛 `IntegrityError`；那是 §4 的**独立加固动作**，且会与导入降级口径冲突）。

### 4.3 修法形状与代价面

**取向先说清**（§1.2）：本仓既有权威取向是「**可见判据（应用层返回/抛错），不靠 DB 级强制**」。故「启用 FK」在本仓属**策略变更（改写入语义）**，**不是**单纯 bug 补齐。

**修法形状（两条互斥路线，须设计者选）**

- **(A) 应用层可见判据（对齐既有取向，推荐为默认）**：`LayeredStore.add_edge`（或 `SpacetimeMemoryEngine.add_edge`）**写入前校验两端存在**，不满足即抛明确判据或返回显式错误；DB FK 仅作**事后体检**（现状 `verify_integrity`/`foreign_key_check` 保留）。
- **(B) 连接级 DB 强制（可选加固，独立动作）**：在**每一条**连接上执行 `PRAGMA foreign_keys=ON`。代价面（实测支撑）：

  1. **改写入语义（最大代价）**：`add_edge` 对新孤儿边**抛 `IntegrityError`**（T2b）——从「永远成功」变「不满足即抛」。需**逐调用点审计**：全仓 `add_edge` 调用点含 `LayeredStore.register_conflict`、`SpacetimeMemoryEngine.update_self`、认知循环、`subgraph_replace`、概念建边、以及 `lingshu/core/longterm_gate.py` 两处。凡「先写边、后写点」或引用了尚未持久化节点的路径会**由静默变抛错**。
  2. **落点：每连接 PRAGMA，非 DDL**：须覆盖 `LayeredStore.conn` ＋ `LayeredStore.increment_access` 的旁路连接 ＋ `activation` 自建连接；DDL 里**已**有 FK 声明（SQLite 不支持 `ALTER TABLE ADD CONSTRAINT`，走表重建会牵动 `_SCHEMA_TABLES`/`SCHEMA_VERSION`）。仓内**零 `CREATE TRIGGER`** 先例。
  3. **存量孤儿边不会被自动清理**（T5a）——启用 FK 只管**新增**写入；存量处置须**独立迁移决策**（§7.3）。
  4. **导入路径会因此失败**（T4a）：含孤儿边的备份导入时 `IntegrityError` **中途抛出**（`import_all` 仅在末尾 `commit()`；代码**无显式 rollback**，处置不明确）。**引用完整的备份在 FK 开启下导入正常**（T3a/b/c 全 OK）⇒「启用 FK 就必然导不进」**不成立**，**只有**含孤儿备份会挂。
  5. **与 `#69`/`#113` 的共存冲突**：`#69` 确立「**缺表降级不失败**」，`#113` 确立「**悬挂事后报告不拦写**」；一旦 FK 强制，含孤儿备份的导入会**从报告变 abort**——两条口径**直接冲突**（§6.3）。

## 5. `#33` 持久化 SELF 未恢复到运行模型（只设计）

### 5.1 判定

**成立**（完全成立）。持久化侧：`update_self` 会把整个 `SelfModel` 以 JSON 写入 **SELF 层节点**（`tags=["self_snapshot"]`），**数据确实落库、可解析回原值**。运行侧：`SpacetimeMemoryEngine.__init__` **无条件**以 `SelfModel(identity=identity)` **新建默认模型**，全仓**无任何从库内 SELF 快照重建 `self_model` 的代码路径**（`SelfModel` **无 `from_dict`**）⇒ 重启后 `values` / `current_goal` / `state_description` / `trust_state` **全部回默认**。

**口径**：应表述为「**恢复失败**」，**不是**「持久化数据已被删除」（数据在库）。

**关键读数（A/B/C/D 段）**：

### 5.3 修法形状（含推荐）

1. **SELF 的序列化版本**：现有 `self_snapshot` 内容是 `json.dumps(SelfModel.to_dict())`＝`asdict(self)`，**无 `version` 字段**（C4），字段增删会**静默漂移**。修法形状：快照加 `version`（旧快照无 `version` 视为 v1）＋提供 `SelfModel.from_dict`（或等价重建函数），并明确「**未知字段忽略 / 缺字段取默认**」的兼容口径。
2. **启动恢复策略**：需在 `SpacetimeMemoryEngine.__init__` 中、`self.self_model = SelfModel(...)` **之后**插入一次性恢复：读 SELF 层 `tags=["self_snapshot"]` 的**最新**节点 → 解析 → 重建 `self_model`。可选源：另存单一权威快照键于 **`engine_meta`**（与 `_schema_version` 同款思路），避免「按时间挑最新 SELF 层节点」在多次 `update_self` 下选错。
3. **「运行 values 回默认」的确切触发点**：`SpacetimeMemoryEngine.__init__` 的 `self.self_model = SelfModel(identity=identity)`——**每次进程构造**即回默认，**与 db 无关**（无论库内有无快照）。故修复落点也**唯一**在此调用之后补回填。
4. **恢复失败的处置**：现状是**静默回退默认**、且 `self_check.self_ok=True` **掩盖**之。修法形状（策略见 S-33-1）：至少让「恢复失败」**可见**（返回值/自检字段显式标注），而非静默。
5. **须防的连带**：`update_self` 的 `link_to_node_id` 建边、`update_trust_state` 的信任史重建（`trust_history` 环形缓冲上限 `TRUST_HISTORY_MAX`、`e_weight` 由最近 3 点算）都应纳入「恢复哪些字段」的范围讨论——**恢复 `trust_state` 但不恢复 `trust_history`** 会让 `e_weight` 与历史**不自洽**（S-33-4）。

```
== 实验1：#139-E（受保护叶）==        [139-E] 受保护叶存活: True   （⇒ 原语层加闸可覆盖此场景）
== 实验2：#36-②（FIFO 上限）==        [36-②] 受保护(最旧)存活: True | 情境层实际条数(可超上限): 4
== 实验3：#36-①（衰减段内联 DELETE）== [36-①] 经 40 次衰减后仍存在: False
```

| 关系 | 共用面（符号锚） | 修一是否顺带消二 |
|---|---|---|
| `#139` ⇄ `#36-②` | **`LayeredStore.delete_node`**（唯一删除原语） | **是**（若把保护判定下沉到该原语） |
| `#139` ⇄ `#36-①` | **无**（衰减段内联 `DELETE FROM nodes`，绕过原语） | **否** |
| `#36-①` ⇄ `#36-②` | 同在 `LayeredStore`，但**一段内联 DELETE、一段走原语** | **否**（`#36` 须改**两处**） |
| `#139` 的原子性/范围/共享引用/计数 | `subgraph_replace` 自身 | **独立**（与保护判定不同判据） |

**推荐结论（含 `#36-①` 旁路是否一并收敛）**

1. **把「保护/不可变层」判定下沉到 `LayeredStore.delete_node` 这一单一谓词——推荐采纳**。一次覆盖 `#139-E` 与 `#36-②`（两件最大交集），并顺带消掉「`enforce_context_cap` 丢弃返回值」「悬空保护登记新增」两个副作用面。
   **附带硬约束**：
   - **忠于 `delete_node -> bool` 契约**（拒 ⇒ 返回 `False`，**不改成抛错**），以保 §2.6 第 1 条既有守卫与 `#139-F`/⑤ 的计数语义；
   - 调用侧（`subgraph_replace` / `enforce_context_cap`）**必须把 `False` 收集并上报**（消 `#139-⑤` 与 `#36` 的「返回被丢弃」）；
   - 该下沉**只**承担「保护/不可变层判据」，**不**承担 `#139` 的原子性/范围/共享引用（那些在 `subgraph_replace` 侧，不同判据）。
2. **`#36-①` 的旁路 `DELETE` 要不要一并收敛 —— 推荐「一并收敛」，但明确标注为改行为、须设计者裁**。
   理由：不收敛则「同一函数内上下两段判据不一致」这一根因**保留**，且未来**任何**新增保护类别都会再次漏掉内联段（判据双份 = 漂移源）。收敛方式（择一，属 S-10 取值）：
   - **(i) 让 `decay_cycle` 情境层删除段改走 `delete_node`** ⇒ 与 `enforce_context_cap`/`subgraph_replace` **三者归一**（代价：删除路径改走原语 + 逐条 `commit()` 语义变化 ⇒ 须核事务/性能）；
   - **(ii) 抽出单一谓词（S-10(a) `is_forgettable`）供四处共用**，内联段保留写法但判据来源唯一。
   **代价诚实标注**：二者**都改 `decay_cycle` 的行为**（含「上/下两段判据从「不一致」变「一致」」这一可观测变化），**不是**纯 bug 补齐 ⇒ 按 §1.3 **必须由设计者拍板**。若不收敛，则 `#36-①` **必须**单独加保护判据（次优但无行为升级）。
3. **`forget_advisor` 的 protections 盲区**（新证）建议同批纳入 S-10(a) 谓词（否则「先 `protect_node` 后被 `forget_advisor` 归档」仍在）——**同为改行为项**。

### 6.2 `#36` 内部：两处修改不可互相抵扣

`#36` **必须改两处**（`decay_cycle` 内联段 ＋ `enforce_context_cap`）；**修 `#36-②` 不消 `#36-①`**，反之亦然。若采纳 §6.1 的下沉，`#36-②` 由原语层自动覆盖，**但仍须单独处置 `#36-①`**——**不得**以「下沉已覆盖 `#36-②`」为由宣称 `#36` 闭合。

### 6.3 `#93` 是否与 `#69`/`#113` 的「降级／事后报告」取向冲突 —— **是，且是硬冲突**

| 关系 | 取向 | 与 `#93` 启用 FK 的冲突 |
|---|---|---|
| `#93` ⇄ `#113` | `#113` 确立「**悬挂事后报告不拦写**」（`import_all` 注释自认「不拦写入」，返回 `dangling_rows`/`integrity_ok`） | **直接冲突**：FK 强制后，含孤儿备份的导入**从「报告」变「abort」**（T4a）。⇒ **禁止**让「`integrity_ok=False` 的报告」与「`IntegrityError` 的 abort」两套语义**并存互斥**（S-93-4 的硬约束）。 |

| `#93` ⇄ `#33` | 无共用函数 | 独立。 |
| `#33` ⇄ 其余三件 | 无共用函数 | 完全独立（SELF 快照面不涉删除/遗忘/边）。 |
