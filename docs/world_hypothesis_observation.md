# 假设验证的主体观测门槛

`SimulationLoop.step()` 每步仍推进物理场景、世界 tick、预测与 WAL。
已存在的候选/已确认假设，只在本次 `perceive()` 的真实观测快照含有主体时推进验证。
这条规则同时适用于 `legacy` 和 `conservative`；后一策略原本已有相同门槛。

主体被遮挡、出视野或身份未决时，验证窗口计数、趋向/背离累计、假设位置、置信和确认/回退事件等待新证据。
其他实体的出现不构成该主体的证据。主体重新出现后沿用已经取得的验证进度，正常确认、跟踪和回退仍生效。
`verify()` 的 `total=0` 不会被算成失败样本，也不会因这次改动变成命中。

范围仅是缺主体观测的门槛；不改生长阈值、确认比例、时间尺度、评分或身份分配。
无效数值、并发调用、重复手动调用私有 `_growth_tick` 等未由本件定义新的处理规则。
`_hypotheses` 是现有验证状态来源；旧节点 `attrs.phase` 展示不同步问题见既有 #192，不在本件处理。
