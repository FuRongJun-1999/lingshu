## 第 1 章 五分钟上手

### 1.1 这站是干什么的

一句话：**有人有活儿，有人能干活，这站负责把两边接上，并保证活儿干完有记录、有信用、有钱的凭据。**

三个核心词，先记住：

| 词 | 什么意思 |
|---|---|
| **悬赏** | 一条任务。发布者出赏金，谁能干谁接 |
| **里程碑** | 一条任务里的**阶段**。可以只有一个（一次干完），也可以有很多个（分阶段验收） |
| **完成码** | 任务干完、发布者确认后，系统给**每个拿钱的人**发一串码。这串码就是"凭据"，拿去线下找发布者领钱 |

### 1.2 三件必须先搞清的事

**第一件：这站不碰钱。**

系统里**没有任何支付功能**，不托管资金，不转账。
赏金数字只是**记录**——记谁该拿多少。真正的钱，是**你和发布者线下自己结**。

> 所以赏金榜上的数字，是"发布者声明的金额"，**不等于钱真的到账了**。这一点我们会在榜单页明确写着，不糊弄你。

**第二件：完成码是唯一的凭据。**

任务结束后，系统会给每个拿钱的人生成一个码。**这个码只有你能看到**，发布者看不到。
你拿着码去找发布者，他填进系统里一验，系统就告诉他：「这码是给 @你的，该付你 ¥500」。然后他线下付给你。

**第三件：声誉是系统说了算。**

你的声誉分**只有系统能加减**。发布者**没有权限**给你减分——他只能"选中你"或"不选你"，分数怎么变是规则定的。
唯一的例外是管理员能手动调整（必须填理由，会留痕）。

### 1.3 第一次进来做什么

```
① 点右上角【注册】
   - 用户名：2~20 个字符，中文/字母/数字/下划线/连字符都行
   - 密码 + 重复密码（没有邮箱验证，注册完就能用）
   - ⚠️ 用户名大小写不敏感：Alice 和 alice 是同一个人

② 注册完你是【普通用户】——能接任务，还不能发任务
   - 想发任务？找管理员给你升到【发布者】

③ 先看【使用指南】（就是这一页）和【任务大厅】

④ 去【个人中心】看看自己的资料、等级、额度
```

### 1.4 四种身份

| 身份 | 能干什么 | 怎么获得 |
|---|---|---|
| **普通用户** | 接任务、提交、建团队、入队、看榜单 | 注册就有 |
| **发布者** | 上面全部 **+ 发任务、验收、分配赏金** | 找管理员开 |
| **管理员** | 什么都能改、能改别人身份、能封人 | 站长（部署这个站的人） |
| **被封禁** | 什么都干不了 | 被管理员封了 |

> **注意**：如果你被封禁了，不是"降级"，是**完全不能操作**。有异议去找管理员。

## 第 2 章 接任务的人怎么用

### 2.1 找活儿

```
点【任务大厅】
   → 看到一堆任务卡片，每张显示：
        · 任务序号（如 XS-0042）
        · 标题
        · 赏金（¥）
        · 难度（简单 / 中等 / 困难 / 专家）
        · 期限
        · 已认领人数
   → 可以用筛选/搜索/排序缩小范围
```

**难度对应什么**（重要，直接影响你的声誉分）：

| 难度 | 完成后你得到 | 超时会扣 | 被判无效交付会扣 |
|---|---|---|---|
| 简单 easy | **+1** | −1 | −1 |
| 中等 medium | **+3** | −1 | −3 |
| 困难 hard | **+6** | −3 | −6 |
| 专家 expert | **+10** | −5 | −10 |

> 越难的活儿，干成了加分越多，但翻车扣得也越狠。**量力而行。**

### 2.2 看任务详情

点进任意任务，你会看到：

```
┌─────────────────────────────────────────────┐
│ XS-0042  给某个脚本加个日志功能                │
│ 赏金 ¥500.00 ｜ 难度：中等 ｜ 期限：2026-11-01 │
│ 状态：可认领                                  │
├─────────────────────────────────────────────┤
│ 【任务描述】                                  │
│   ……具体要做什么……                            │
├─────────────────────────────────────────────┤
│ 【里程碑】                                    │
│   M1  实现日志输出   占比 40%  ← 决策点       │
│       验收标准：                              │
│        · 运行 xxx 退出码为 0                  │
│        · 贴出改前改后的读数对照                 │
│   M2  写测试用例     占比 60%                 │
│       验收标准：……                            │
├─────────────────────────────────────────────┤
│ 【已认领的人】                                │
│   @alice（2 小时前）  @bob（1 小时前）         │
│   ⚠️ 你看不到他们交了什么（防抄袭）             │
├─────────────────────────────────────────────┤
│ 【我可以做什么】 ← 这排按钮是系统给的           │
│   [认领任务] [放弃认领] [提交交付]             │
└─────────────────────────────────────────────┘
```

**重点**：
- **你能看到"谁接了"，但看不到别人交了什么。** 这是故意的——防止互相抄。
- 你能看到**别人做到第几个里程碑了**（进度条），但看不到具体内容。
- 那排按钮**是服务器算出来给你的**。如果你看到某个按钮是灰的，把鼠标放上去会显示原因（比如"仅发布者可验收"）。**不要猜能不能点，看按钮。**

### 2.3 认领

```
任务详情页 → 点【认领任务】→ 完成
```

**认领时要知道的**：

| 规则 | 说明 |
|---|---|
| 期限 | 认领后 **72 小时**内必须交付，超时自动释放 + 扣声誉 |
| 并发上限 | 你同时能接几个任务**受等级限制**（1 级只能接 2 个） |
| 多人可接 | 同一个任务**允许多人同时接**，最后发布者选 |
| 团队接 | 有团队的话可以"以团队名义接"（见第 4 章） |

**如果额度满了**，系统会告诉你：「你当前并发认领 N 个，已达上限 M」。要么交付一个，要么放弃一个。

**想反悔？** 点【放弃认领】。**主动放弃不扣声誉**，任务回到大厅让别人接。

### 2.4 干活 & 提交

**提交入口在任务详情页**（不在个人中心）。

```
任务详情页 → 点【提交交付】
   → 填【说明】：你干了什么、怎么验证、关键读数
   → 可以传【文件】（单个最大 20MB，一个任务总共 200MB）
   → 可以贴【链接】（放到别处的证据）
   → 提交
```

**提交内容的写法建议**（这不是系统强制，但能让你更快通过验收）：

```
✅ 好的提交：
   「改了 xxx.py 第 42 行，把 log 级别从 DEBUG 改成 INFO。
    复跑命令：python -m pytest tests/
    改前读数：12 passed in 3.2s
    改后读数：12 passed in 3.1s
    附件：diff.patch」

❌ 差的提交：
   「改好了，应该没问题」
```

> **为什么？** 因为发布者是**照着任务里写好的验收标准**一条条核对你的提交。
> 你把读数贴清楚，他几秒钟就能判过；你写得含糊，他就只能退回让你重来，白白浪费一轮。

### 2.5 验收结果

提交后，发布者会给你三种结果之一：

| 结果 | 含义 | 你的声誉 |
|---|---|---|
| **通过** | 活儿合格，进入下一阶段或分配 | 正常加分 |
| **退回返工** | 还不行，改改再来 | **不扣分**（只是消耗一轮机会） |
| **判定无效交付** | 交付是假的/完全不对，发布者**必须填理由** | **扣 base 分**（如 expert 扣 10） |

**返工有轮次上限**（默认 3 轮）。轮次用完了还没过，就会按"无效交付"处理。

**如果你觉得发布者判得不公**：可以**提起争议**。争议会记录在案，管理员可以复核，必要时**撤销扣分**（撤销也留痕）。

### 2.6 拿钱：完成码

**这是最关键的一步，慢慢看。**

```
任务全部完成、发布者验收通过、发布者点了【分配】
        ↓
系统给每个该拿钱的人生成一个码（比如给 @alice 一个，给 @bob 一个）
        ↓
你打开【个人中心 → 我的完成码】，看到属于你自己的码
   ┌──────────────────────────┐
   │ XS-0042                  │
   │ 你的码：X7K9P2M4QW        │
   │ 金额：¥500.00             │
   │ 状态：待核销              │
   └──────────────────────────┘
        ↓
你线下联系发布者：「我是 alice，XS-0042，码是 X7K9P2M4QW」
        ↓
发布者在任务页【填写完成码】→ 系统验证 → 显示「✅ 此码属于 @alice，应支付 ¥500.00」
        ↓
发布者线下把钱给你 → 他点核销 → 你的码变成【已核销】
        ↓
所有码都核销完 → 任务自动关闭
```

**几个必须知道的点**：

| 点 | 说明 |
|---|---|
| **发布者看不到你的码** | 他只能"验证你给的码对不对"，不能自己查。所以他不核销，你就没法完成流程 |
| **一个码只核销一次** | 重复提交会说"已核销" |
| **码不要公开** | 谁拿到码都能冒充你去核销。**只私下发给发布者** |
| **发布者一直不核销** | 30 天后任务自动关闭，发布者会被记一条"未核销"（**不扣他声誉，但留痕**） |
| **金额改过怎么办** | 如果发布者改了分配金额，**旧码作废**，系统会给你发新码。以【我的完成码】里显示的最新码为准 |

### 2.7 落选了怎么办

同一个任务多人接，最后发布者只选了一部分人。**落选不是白干。**

| 情况 | 你得到 |
|---|---|
| 你**提交过有效交付**，但没被选中 | **落选补偿分**：简单 +1 / 中等 +2 / 困难 +3 / 专家 +4 |
| 你**只认领了，什么都没交** | **0 分**（所以别乱占坑） |
| 你**主动放弃** | **0 分**（不扣分） |
| 你**超时没交** | **扣分**：简单/中等 −1，困难 −3，专家 −5 |

> **落选补偿分是有意设计的**：不然没人愿意去竞争难的活儿。
> 但注意——**光认领不交付是拿不到这个分的**，必须有实际提交。

## 第 3 章 发任务的人怎么用

> **前提**：你得先是【发布者】身份。没有的话找管理员开。

### 3.1 发一条任务

\`\`\`
【任务大厅】→ 右上角【发布任务】
\`\`\`

要填的东西：

| 字段 | 说明 | 注意 |
|---|---|---|
| **标题** | 一句话说清要做什么 | 最多 120 字 |
| **描述** | 详细说明、背景、参考资料 | 写清楚，能少一半返工 |
| **难度** | 简单 / 中等 / 困难 / 专家 | **手选**，直接决定声誉分（1/3/6/10） |
| **总赏金** | 人民币，必填 | 只能填正数，金额是字符串精确到分 |
| **期限** | 什么时候要 | 到了没人交任务就自动过期 |
| **里程碑** | 见下 | 至少 1 个，占比加起来必须 = 100% |

### 3.2 设计里程碑（这是最重要的部分）

**里程碑 = 任务的阶段。** 你的活儿是"一次干完"还是"分几步走"，全在这里决定。

#### 情况一：一次干完（整体型）

只建 **1 个里程碑**，占比 100%，勾上"决策点"。

\`\`\`
M1  完成整个任务    占比 100%   ☑ 决策点
    验收标准：
     · 运行 python -m pytest 退出码为 0
     · 贴出改前/改后读数对照
\`\`\`

#### 情况二：先看 demo 再决定（Demo 型）

建 **2 个以上里程碑**，第一个是 demo。

\`\`\`
M1  做出可运行的 demo    占比 30%   ☑ 决策点
    验收标准：· demo 能跑起来 · 贴运行截图或录屏链接
M2  完成剩余功能         占比 70%
    验收标准：· 全部测试通过 · 提交代码
\`\`\`

#### 情况三：多级（想分几步就分几步）

\`\`\`
M1  原型      占比 20%   ☑ 决策点
M2  核心功能   占比 30%   ☑ 决策点
M3  优化打磨   占比 25%   ☑ 决策点
M4  文档交付   占比 25%
\`\`\`

**决策点是什么意思？**

> 每到一个**决策点**，系统会停下来，让你**选人**：
> 谁继续往下做，谁到此为止（落选，给补偿分），这一阶段付多少钱。
>
> 所以：**决策点 = 你行使选择权的时刻**。
> 不勾决策点 = 一路做到底，中途不打断。

### 3.3 写验收标准（**必须能机械复核**）

**每个里程碑都必须写验收标准，至少 1 条。** 这是硬性要求——写不好系统不让你发。

**为什么这么严？** 因为验收标准就是**你事后判定的唯一依据**。你写"质量好"，三天后你自己都不知道算不算好，对方也不服。

**系统会拒绝这些词**：

> 质量好 / 看得过去 / 尽量 / 差不多 / 优化一下 / 差不多就行 / 快 / 好一点 / 完善 / 美观 / 能用就行 / 酌情 / 视情况

写这些会被打回来，提示你：「验收标准必须可机械复核，请写清『谁在什么条件下会红/会绿』」。

**好标准的公式**：**谁 + 在什么条件下 + 会红还是会绿**

| ❌ 不行 | ✅ 可以 |
|---|---|
| 代码质量好 | 运行 \`python -m pytest\` 退出码为 0 |
| 性能优化一下 | \`time python bench.py\` 输出 < 2.0s（改前 5.3s） |
| 文档完善 | \`docs/README.md\` 含"安装/使用/常见问题"三节，每节 ≥ 200 字 |
| 界面美观 | 在 375px 宽度下无横向滚动条（附截图） |
| 功能差不多能用 | 点击【导出】按钮后 3 秒内下载到 CSV，字段为 id,name,date |

> **口诀**：如果这条标准，**换个人来判也能判出一样的结果**，那就是合格的。

### 3.4 发布

填完点【发布】→ 任务从"草稿"变成"可认领"，出现在任务大厅。

\`\`\`
草稿 → 发布 → 可认领 → 有人接 → 进行中 → …
\`\`\`

**发布后还能改吗？** 能，但要走**变更单**（见 3.7）。

### 3.5 看别人干活

任务页上你能看到：

| 看得到 | 看不到 |
|---|---|
| 谁认领了（@用户名 / @团队名） | 别人交的**具体内容** |
| 每个人做到第几个里程碑了 | |
| 谁提交了、什么时候提交的 | |

> **为什么看不到别人的内容？** 因为这是**竞标**。如果你能看，你就能抄。
> **但你是发布者——你能看到每个人交给你验收的内容**（那是必须的）。

### 3.6 验收

有人提交后，你在任务页会看到待验收的条目（个人中心【发布侧 → 需审核】有红点）。

三个按钮，想清楚再点：

| 按钮 | 什么时候用 | 后果 |
|---|---|---|
| **通过** | 确实符合验收标准 | 对方进入下一阶段，或等待分配 |
| **退回返工** | 还差点，但方向对 | **不扣分**，消耗对方一轮机会（默认共 3 轮） |
| **判定无效交付** | 交付是假的/完全不对/糊弄 | **扣对方 base 分**，**必须填理由** |

> **强烈建议**：能"退回返工"就别"判定无效交付"。
> 返工不扣分，是正常协作；判无效交付是**重罚**，还要求你写理由，而且对方可以提争议。**别把它当情绪出口。**

### 3.7 改需求：变更单

发布后想改赏金、改期限、改里程碑？**走变更单，不要想着直接改。**

\`\`\`
任务页 → 【发起变更】
   → 选类型：赏金 / 期限 / 里程碑 / 其他
   → 填新值
   → 填理由（必填）
   → 提交
\`\`\`

**规则**：

| 变更 | 限制 |
|---|---|
| **改赏金** | 新值**不能低于已经分配出去的总额**。可以随时改（**分配完之后也能改**） |
| **改期限** | 只能**往后延**。想提前？得找管理员 |
| **改里程碑** | 已经"通过"的里程碑不能删；所有里程碑占比加起来必须还是 100% |
| 其他 | 只留备注，不改状态 |

> **为什么改赏金有下限？** 因为如果已经说了给 alice 500、给 bob 300（共 800），你把总赏金改成 500，账就对不上了。系统不让你造出这种矛盾。

### 3.8 决策点：选人

到了决策点，任务会变成"待裁决"状态，等你处理。

\`\`\`
任务页 → 【决策】
   → 看到所有到达这个决策点的人
   → 选一个继续（或结束）
   → 没被选的人 → 落选，自动发补偿分
   → 填这一阶段付多少钱（按里程碑占比自动算，可调）
   → 确认
\`\`\`

**选人的依据**：看他们的提交内容 + 你要的验收标准。**这是你的权力，也是你的责任。**

### 3.9 中途取消任务

活儿不干了 / 需求变了 / 找到别的方案了 → 可以取消。

\`\`\`
任务页 → 【取消任务】
   → 系统自动算出补偿金下限（已完成里程碑占比 × 总赏金）
   → 你可以往上加
   → 填取消理由
   → 确认
\`\`\`

**补偿金怎么算**：

\`\`\`
例：总赏金 ¥1000，3 个里程碑各占 33%/33%/34%
    有人已经完成了 M1 和 M2
    补偿金下限 = 1000 × (33% + 33%) = ¥660
    你可以选择给 ¥660、¥800、¥1000……
\`\`\`

**补偿金去哪**：进入被取消者的**累计赏金榜**（也生成完成码）。
**声誉怎么变**：取消的任务**不产生声誉分**（不加不减）。

### 3.10 分配赏金（最关键的收尾）

任务做完了，该分钱了。

\`\`\`
任务页 → 【分配赏金】
   → 列出所有应该拿钱的人
   → 每个人填金额
   → 确认
   → 系统为每个人生成一个完成码
\`\`\`

**分配界面上你能看到的**：

\`\`\`
┌──────────────────────────────────────────────┐
│ 分配赏金 · XS-0042                            │
│ 总赏金：¥1000.00   已分配：¥800.00            │
├──────────────────────────────────────────────┤
│ @alice    ¥500.00   [可编辑]   码状态：待核销  │
│ @bob      ¥300.00   [可编辑]   码状态：待核销  │
├──────────────────────────────────────────────┤
│ ⚠️ 你看不到码的内容——码只发给对应的人           │
│    他们会把码告诉你，你在下面验证               │
├──────────────────────────────────────────────┤
│ 【填写完成码】 [________________]  [验证]      │
└──────────────────────────────────────────────┘
\`\`\`

**你能随时改分配** —— 包括任务已经进入"待核销"之后。

| 改动 | 结果 |
|---|---|
| 改一个**还没核销**的人的金额 | 旧码作废，系统给他发新码 |
| 改一个**已经核销**的人 | ❌ 不允许（钱已经确认了） |
| 加一个新的人 | 生成一个新码 |
| 总分配额 | 不能超过总赏金 |

### 3.11 核销完成码

\`\`\`
① 对方线下联系你：「我是 alice，XS-0042，码是 X7K9P2M4QW」
② 你在任务页【填写完成码】里输入这串码
③ 系统验证：
     ✅ 成功 → 显示「此码属于 @alice，应支付 ¥500.00」
              → 你线下把钱付给 alice
              → 该码标记为【已核销】
     ❌ 失败 → 显示「码无效或已核销」
④ 所有码都核销完 → 任务自动关闭
\`\`\`

**注意**：
- **你永远看不到码本身**，只能验。所以你没法自己造码糊弄。
- 输错了没关系，有次数限制（每分钟 5 次），别乱试（防暴力破解）。
- 失败的提示**不区分**"码不存在"和"已核销"——这是为了防止有人拿系统当查询器试探。

**如果你一直不核销**：30 天后任务自动关闭，你会被记一条"未核销"。**不扣你声誉，但记录在案。**

### 3.12 你的发布侧面板

\`\`\`
个人中心 → 我的任务 → 【发布侧】
├── 已发布    ← 进行中的
├── 需审核    ← 有提交等你验收  ★ 带红点数字
└── 已完成    ← 已关闭的
\`\`\`

## 第 4 章 团队怎么用

### 4.1 建团队

\`\`\`
【团队】→ 【创建团队】
   → 团队名（最多 32 字，全局唯一）
   → 头像
   → 简介（最多 300 字）
   → 创建
\`\`\`

**建完你就是队长。** 注意：**一个人同时只能在一个团队里**。你自己建了队，就占了你的名额。

### 4.2 邀请人

\`\`\`
团队页 → 【邀请成员】
   → 输入对方的**用户名**（注意：大小写不敏感，输 alice 或 Alice 都行）
   → 发送邀请
\`\`\`

对方会在【通知】里看到邀请，**同意后才入队**。邀请 **7 天**内有效。

**队长能做的**：邀请 / 踢人 / 转让队长 / 解散团队。

### 4.3 以团队名义接任务

\`\`\`
任务详情页 → 点【以团队认领】
   → 任务页会显示「@你的团队名 接取」
\`\`\`

**关键规则**：

| 项 | 说明 |
|---|---|
| 任务挂谁头上 | **挂团队**（不挂你个人） |
| 谁提交 | **只有队长能提交**（成员不能直接交） |
| 完成码给谁 | **给队长** |
| 占谁的额度 | **优先占团队额度**；团队额度满了，**可以用你个人的额度**接 |
| 声誉分给谁 | 任务完成后，**队长勾选参与人**，分只给被勾选的人 |

### 4.4 团队额度 vs 个人额度

**额度 = 你同时能接几个任务。**

| | 1 级 | 等级高了 |
|---|---|---|
| **个人** | 2 个 | 最多 10 个 |
| **团队** | 5 个 | 最多 30 个 |

团队额度不够时，**队长可以用自己的个人额度接**（任务还是挂团队头上）。这样不会因为团队满了就接不了活。

### 4.5 团队任务收尾：分配

任务完成后，**码是发给队长的**。队长要做两件事：

\`\`\`
团队页 → 【分配赏金】
   ① 填金额：每个成员分多少
   ② 勾选参与人：这次活儿谁参与了（声誉只给勾上的人）
\`\`\`

**⚠️ 界面上会显示这句话，请认真读**：

> **这里的赏金分发只影响个人资料信息和排行榜，实际具体奖金分发需要队长自行分发**

**什么意思？**
- 你在系统里填的数字，**只影响榜单显示和个人资料**——系统不会替你把钱转给成员
- **真正的钱，要你自己线下分给成员**
- 所以：**别以为填完系统就自动发了**，那只是个记录

### 4.6 声誉分怎么分给成员

**系统自动算，你只需要勾人。**

\`\`\`
公式：每人 = max(1, round(基础分 × (1 − 0.2 × (人数 − 1))))

以"专家"任务（基础分 10）为例：
   1 人参与 → 每人 +10
   2 人参与 → 每人 +8
   3 人参与 → 每人 +6
   4 人参与 → 每人 +4
   5 人参与 → 每人 +2
   6 人及以上 → 每人 +1（保底）
\`\`\`

**为什么要衰减？** 因为人越多，每个人的贡献越稀薄。**这是有意设计，防止"拉一堆人进来分分"。**

### 4.7 团队等级

**团队等级分 = 建队之后，成员获得的声誉之和。**

| 关键点 | 说明 |
|---|---|
| 只算**建队后**的 | 成员在入队之前攒的分，不算团队分 |
| 成员**退队/被踢** | 他贡献的那部分分**从团队分里扣掉** |
| 后果 | 团队等级**可能因此下降**（我们知道这有点痛，但这是为了防止"刷分后退队"） |
| 赏金 | 已经分出去的赏金**不受影响** |

### 4.8 退出 / 解散

| 动作 | 谁 | 后果 |
|---|---|---|
| 主动退队 | 成员 | 他的建队后得分从团队分扣除 |
| 踢人 | 队长 | 同上 |
| 转让队长 | 队长 | 对方成为队长 |
| 解散团队 | 队长 | 团队标记为已解散（历史保留） |

## 第 5 章 声誉、赏金、等级

### 5.1 声誉分：怎么来的

**一条铁律：声誉分只有系统能加减。**

发布者**没有**任何按钮能给你加分或减分。他只能"选中你"或"不选你"——分数怎么变，是**规则**决定的，不是他的心情。

### 5.2 加分表

| 场景 | 加多少 |
|---|---|
| 完成任务（个人） | 简单 **+1** / 中等 **+3** / 困难 **+6** / 专家 **+10** |
| 完成任务（团队，n 人参与） | 每人 \`max(1, round(base × (1 − 0.2×(n−1))))\` |
| **落选**（提交过有效交付） | 简单 **+1** / 中等 **+2** / 困难 **+3** / 专家 **+4** |
| 阶段性结算（Demo 型过一关） | 按该里程碑占比折算，最少 +1 |

### 5.3 扣分表

| 场景 | 扣多少 | 谁触发 |
|---|---|---|
| **超时未交付** | 简单/中等 **−1** / 困难 **−3** / 专家 **−5** | 系统自动 |
| **无效交付** | 简单 **−1** / 中等 **−3** / 困难 **−6** / 专家 **−10** | 发布者判定（**必须填理由**） |
| 管理组手动调整 | 任意 | 管理员（**必须填理由**，留痕） |

### 5.4 不扣分的情况（放心）

| 情况 | 声誉 |
|---|---|
| **主动放弃认领** | 0，不扣 |
| 任务被发布者**中途取消** | 0，不扣（但有补偿金） |
| **被退回返工** | 0，不扣（只是消耗一轮机会） |
| 提起争议 | 0，不扣 |
| 发布者一直不核销码 | 0，不扣（只给发布者留痕） |

> **"退回返工"和"判定无效交付"是天壤之别**：前者是正常协作，后者是重罚。发布者不该混用。

### 5.5 只统计"正常结束"的任务

- **只有正常关闭（closed）的任务**才产生结算声誉
- **被取消（cancelled）/ 过期（expired）的任务不产生结算分**
- 但——**超时扣分照扣**（那是"行为扣分"，不是"任务结算"）

### 5.6 赏金榜：一个必须说清的口径

> ## ⚠️ 赏金金额由发布者自行申报，系统不验证真实支付
>
> 榜单上显示的是**"发布者声明的分配额"**，**不等于钱真的到账了**。
> 本系统不托管资金、不转账、不碰钱。**请以线下实际结算为准。**

**为什么要专门说这个？** 因为如果我们不写，你会以为榜上的数字是真的钱。**我们不想骗你。**

### 5.7 榜单

四个榜：

| 榜 | 统计范围 | 排序 |
|---|---|---|
| 声誉榜 · 永久 | 全部时间 | 累计声誉分 |
| 声誉榜 · 月度 | **自然月**（每月 1 号清零重算） | 当月声誉分 |
| 赏金榜 · 永久 | 全部时间 | 累计赏金 |
| 赏金榜 · 月度 | 自然月 | 当月赏金 |

**不做团队榜**（团队等级在团队页看）。

**赏金榜只统计正常结束的任务**（含取消时付的补偿金）。

### 5.8 等级

**等级 = 你能同时接几个任务**（目前唯一的权益）。

#### 个人等级（10 级）

| 等级 | 需要累计声誉 | 能同时接几个 |
|---|---|---|
| Lv.1 | 0 | **2** |
| Lv.2 | 10 | 3 |
| Lv.3 | 30 | 4 |
| Lv.4 | 60 | 5 |
| Lv.5 | 100 | 6 |
| Lv.6 | 150 | 7 |
| Lv.7 | 210 | 8 |
| Lv.8 | 280 | 9 |
| Lv.9 | 360 | 10 |
| Lv.10 | 450 | 10 |

#### 团队等级（30 级，节选）

| 等级 | 需要累计声誉（建队后） | 能同时接几个 |
|---|---|---|
| Lv.1 | 0 | **5** |
| Lv.3 | 90 | 6 |
| Lv.5 | 300 | 8 |
| Lv.10 | 1350 | 12 |
| Lv.15 | 3150 | 17 |
| Lv.20 | 5700 | 21 |
| Lv.25 | 9000 | 25 |
| Lv.30 | 13050 | **30** |

> **等级名字**（如"见习/正式/资深"）还没定，现在统一显示 Lv.N。
> **等级以后可能解锁别的东西**（比如更大的上传空间、特殊徽章），现在的架构留了位置。

## 第 6 章 让 agent 帮你干活

### 6.1 能做什么

你的 agent（Claude / GPT / 自研脚本 / 随便什么）可以**代替你**：

| 能力 | 对应操作 |
|---|---|
| 一键阅读悬赏 | 列出/搜索任务大厅 |
| 一键接赏 | 认领任务 |
| 一键提交 | 提交交付内容 |
| 一键发布 | 发任务（需要发布者权限） |
| 拿码 | 查看自己的完成码 |
| 管团队 | 建队、邀请、看成员 |

### 6.2 第一步：生成 API Token

\`\`\`
个人中心 → 【API Token】→ 【创建 Token】
   → 起个名字（比如 "my-agent"）
   → 创建
   → ⚠️ 明文只显示一次，立刻复制保存！
\`\`\`

**Token 是什么**：一串代表**你的账号**的密钥。谁拿到它，谁就能以你的身份操作。

| 规则 | 说明 |
|---|---|
| 权限 | **全权**（跟你本人一样） |
| 有效期 | 长期，直到你**吊销** |
| 吊销 | 个人中心里点一下，立刻失效 |
| 保管 | **不要写进代码、不要提交到 git、不要发给别人** |

> **Agent 必须用 Token。不允许匿名接任务。** 原因很简单：声誉得有个归属，而且不能让脚本随便刷。

### 6.3 三种接入方式

#### 方式一：OpenAPI（最通用）

你的 agent 直接读：

\`\`\`
https://你的域名/api/openapi.json
\`\`\`

这是**完整的接口说明书**（机器可读）。任何能调 HTTP 的 agent 都能自己学会怎么用。

人类看的交互式文档在：\`https://你的域名/api/docs\`

#### 方式二：CLI（最顺手）

\`\`\`bash
xs login                      # 登录（存 token）
xs tasks                      # 看任务大厅
xs tasks --difficulty=expert  # 只看专家难度
xs show XS-0042               # 看任务详情
xs claim XS-0042              # 接任务
xs submit XS-0042 --body "改好了" --file diff.patch
xs codes                      # 看我的完成码
xs whoami                     # 我是谁
\`\`\`

#### 方式三：MCP（最省事，给支持 MCP 的 agent）

MCP server 暴露这些工具，agent 直接调用：

| 工具 | 干什么 |
|---|---|
| \`list_tasks\` | 列出任务 |
| \`get_task\` | 看任务详情 |
| \`claim_task\` | 接任务 |
| \`submit_delivery\` | 提交交付 |
| \`list_my_codes\` | 看我的码 |
| \`redeem_code\` | 核销码 |
| \`list_teams\` | 看团队 |

### 6.4 给 agent 的一段话（可以直接贴给它）

> 你在一个悬赏平台上代表我干活。你有 API Token，通过它调用接口。
>
> **接入方式**：
> - 读 \`/api/openapi.json\` 了解所有接口
> - 认证头：\`Authorization: Bearer <你的token>\`
>
> **常用流程**：
> 1. \`GET /api/tasks\` 看有什么活儿
> 2. \`GET /api/tasks/{serial}\` 看详情（**注意看里程碑和验收标准**）
> 3. \`GET /api/tasks/{serial}/allowed-actions\` **确认我能做什么**（别猜）
> 4. \`POST /api/tasks/{serial}/claim\` 接任务
> 5. \`POST /api/tasks/{serial}/submissions\` 交活儿（body + links + files）
> 6. \`GET /api/me/codes\` 拿完成码
>
> **纪律**：
> - **每次操作前先调 \`allowed-actions\`**，它告诉你当前能做哪些动作、不能做的原因是什么
> - 提交内容要**可复跑、有读数**，不要写"已完成"这种话
> - 遵守限速，别疯狂重试

### 6.5 防刷规则（agent 要知道）

| 动作 | 限制 |
|---|---|
| 通用 API | 300 次 / Token / 分钟 |
| 认领 | 60 次 / 用户 / 小时 |
| 提交 | 30 次 / 用户 / 小时 |
| 发任务 | 20 次 / 用户 / 天 |
| 填完成码 | 5 次 / 用户 / 分钟 |

超了会返回 \`429 rate_limited\`。**退避重试，别硬刷。**

## 第 7 章 管理员手册

### 7.1 你是谁

**管理员 = 把这个站部署到服务器上的人。**

第一个管理员是**部署时写进去的**。之后，**只有管理员能给别人管理员权限**。

### 7.2 你能做什么

| 能力 | 说明 |
|---|---|
| **改用户角色** | 普通用户 ↔ 发布者 ↔ 管理员 |
| **封禁 / 解封** | 封禁后对方完全不能操作 |
| **改任何任务** | 不管是不是你发的 |
| **看所有提交内容** | 包括别人的（排障/仲裁用） |
| **手动调整声誉** | **必须填理由**，会留痕 |
| **看审计日志** | 所有操作记录 |
| **用 Django Admin** | \`/admin/\` —— 数据库级别的后台，什么都能改 |

### 7.3 日常要做的事

\`\`\`
① 有人申请当发布者 → 去后台给他升级
② 有人提争议 → 看证据 → 决定是否撤销扣分
③ 发现刷榜/小号 → 封禁
④ 定期看审计日志，发现异常操作
\`\`\`

### 7.4 封禁的正确用法

**封禁不是"降级"，是完全停权。**

\`\`\`
后台 → 用户 → 【封禁】→ 填理由（必填）
\`\`\`

**什么时候该封**：恶意刷单、多账号刷榜、辱骂、上传违规内容、攻击系统。

**什么时候不该封**：只是活儿没干好、有争议、跟你意见不合。**那些走正常流程。**

### 7.5 手动调整声誉（慎用）

\`\`\`
后台 → 声誉调整 → 选人 → 填分值（可正可负）→ 填理由 → 确认
\`\`\`

**这是唯一能绕过"系统自动判定"的口子，所以：**
- **必须填理由**（系统强制）
- **全程留痕**（审计日志能查到是你调的）
- **只用于纠正错误**（比如争议仲裁后撤销错误扣分），**不要用来奖励关系好的人**

### 7.6 一些你必须知道的坑

| 坑 | 说明 |
|---|---|
| **赏金金额不可验证** | 系统不碰钱。榜上的数字是发布者自己报的，可能是假的。**这是已知限制，不是 bug** |
| **没有邮箱验证** | 理论上可以一人多号刷榜。MVP 阶段靠你人工发现 + 封禁 |
| **没有 2FA** | 你自己的管理员账号请用强密码，最好限制登录来源 IP |
| **备份** | 数据库每天备份，**媒体文件和数据库分开存**，密钥（SECRET_KEY 等）必须离线备份一份 —— **丢了码就全废** |
| **恢复演练** | **每季度真恢复一次**。没演练过的备份等于没有备份 |

## 第 8 章 常见问题

### 接任务相关

**Q：我可以同时接几个任务？**
A：看你等级。1 级能接 2 个，最高 10 级能接 10 个。团队 1 级能接 5 个，最高 30 级能接 30 个。

**Q：接了不想做了怎么办？**
A：点【放弃认领】。**不扣声誉**，任务回大厅。但别养成习惯——占着坑不干活，别人就接不了。

**Q：72 小时不够怎么办？**
A：到期没交会自动释放并扣分。如果确实需要更多时间，**提前跟发布者沟通**，让他延长任务期限（走变更单）。

**Q：同一个任务很多人接，我能不能看到别人交了啥？**
A：**不能**。你能看到"谁接了"和"做到第几个里程碑了"，但看不到具体内容。这是为了防止互相抄袭。

**Q：我怎么知道现在能做什么？**
A：**看任务页的按钮**。那排按钮是服务器算出来的。灰掉的按钮，鼠标放上去会告诉你为什么不能点。**不要猜。**

### 发布任务相关

**Q：我为什么发不了任务？**
A：你可能是【普通用户】。发布任务需要【发布者】身份，找管理员开。

**Q：验收标准为什么老是不让我过？**
A：你写了不可机械复核的词（"质量好""差不多"之类）。改成"谁 + 什么条件 + 会红还是会绿"的形式。**参考第 3.3 节的对照表。**

**Q：能不能改已经发布的任务？**
A：能，走【变更单】。赏金可以随时改（但不能低于已分配总额），期限只能往后延。

**Q：我想少给点赏金行不行？**
A：如果已经分配出去了（比如承诺给 alice 500），总额就不能低于已分配的总和。**没分配之前随便改。**

**Q：我能中途不干了吗？**
A：可以，点【取消任务】。要付**补偿金**（已完成里程碑占比 × 总赏金，你可以往上加）。

### 完成码相关

**Q：为什么我看不到码？**
A：**设计如此。** 码是发给"拿钱的人"的凭据。你能验，不能看——这样你就没法自己造码。

**Q：码长什么样？**
A：10 位，只用不容易看错的字符（去掉了 0、O、1、I、L）。比如 \`X7K9P2M4QW\`。

**Q：对方把码给我了，我填进去说无效？**
A：三种可能：① 码输错了；② 这个码已经核销过了；③ 码是旧的（你改过分配金额，旧码作废了）。**让他在【我的完成码】里重新看一眼最新的码。**

**Q：我一直不核销会怎样？**
A：30 天后任务自动关闭，你被记一条"未核销"。**不扣声誉，但记录在案。**

**Q：码泄露了怎么办？**
A：立刻改分配金额（哪怕只改 1 分钱），**旧码会自动作废**，系统给对方发新码。

### 声誉相关

**Q：发布者能扣我分吗？**
A：**不能。** 他只能"退回返工"（不扣分）或"判定无效交付"（扣分，必须填理由）。没有任何接口能让他直接改你的分。

**Q：被误判了怎么办？**
A：**提起争议**。管理员可以复核，必要时撤销扣分（撤销也留痕）。

**Q：落选了有分吗？**
A：有，但**必须提交过有效交付**。简单 +1 / 中等 +2 / 困难 +3 / 专家 +4。光认领不交是 0 分。

**Q：任务被取消了，我有分吗？**
A：声誉 **0**（取消的任务不产生结算分），但**有补偿金**（进赏金榜）。

**Q：声誉会过期吗？**
A：**永久榜不过期**。月度榜每月 1 号清零重算，但那只是另一个统计口径，你的累计分不受影响。

### 团队相关

**Q：我能加几个团队？**
A：**1 个**。

**Q：成员能提交任务吗？**
A：**不能，只有队长能提交。**

**Q：团队分怎么算的？**
A：**建队之后**成员获得的声誉之和。入队前攒的分不算。

**Q：成员退队了，团队分会掉吗？**
A：**会掉。** 他贡献的那部分会从团队分里扣掉。这是为了防止"刷分后退队"。

**Q：团队额度满了怎么办？**
A：队长**可以用自己的个人额度接**，任务还是挂团队头上。

**Q：我在团队页填的赏金分配，系统会自动发钱吗？**
A：**不会。** 那句话写得很清楚：**"这里的赏金分发只影响个人资料信息和排行榜，实际具体奖金分发需要队长自行分发"**。系统只记录，钱要队长自己线下分。

### 赏金与榜单

**Q：钱是系统给的吗？**
A：**不是。系统完全不碰钱。** 只发码，你拿码去找发布者线下要钱。

**Q：榜上的金额是真的吗？**
A：**是发布者申报的，系统不验证。** 所以榜上的数字不等于钱真到账了。**请以线下实际结算为准。**

**Q：为什么月榜会清零？**
A：不是"清零你的分"，是**换一个统计窗口**。你的永久累计分一直都在。

### Agent 相关

**Q：agent 能匿名干活吗？**
A：**不能。** 必须用 API Token，代表某个具体账号。不然声誉没处算。

**Q：Token 泄露了怎么办？**
A：去个人中心**立刻吊销**，然后建一个新的。

**Q：agent 被限速了怎么办？**
A：看到 \`429\` 就退避重试。别硬刷，会被当成攻击。

### 其他

**Q：用户名能改吗？**
A：**不能。** 用户名是你的唯一标识（声誉、任务、团队都挂在上面）。显示名可以改。

**Q：忘记密码了怎么办？**
A：MVP **没有邮箱验证和找回密码**。找管理员在后台重置。

**Q：能注册几个账号？**
A：技术上可以，但**一人多号刷榜是明确违规**，会被封禁。**正式版会加邮箱验证来堵这个口子。**

**Q：有没有手机 App？**
A：没有。网页是手机友好的。

## 附录 A：一页纸速查

### 接任务的人

\`\`\`
注册 → 任务大厅 → 看详情（读里程碑 + 验收标准）
  → 认领（72h 期限）
  → 干活 → 任务页【提交交付】（贴读数 + 传文件）
  → 等验收（通过 / 返工 / 无效）
  → 任务结束后 → 个人中心【我的完成码】拿码
  → 线下找发布者 → 他核销 → 完事
\`\`\`

### 发任务的人

\`\`\`
【发布任务】→ 填标题/描述/难度/赏金/期限
  → 设计里程碑（1 个 = 一次干完；多个 = 分阶段）
  → **每个里程碑写可机械复核的验收标准**（否则发不出去）
  → 发布
  → 有人提交 → 【验收】（通过/返工/无效）
  → 决策点 → 【选人】
  → 做完 → 【分配赏金】→ 生成码
  → 对方给码 → 【填写完成码】→ 核销
  → 全部核销 → 任务自动关闭
\`\`\`

### 三条铁律

\`\`\`
① 系统不碰钱 —— 只发码，钱线下结
② 声誉系统说了算 —— 发布者只能选人，不能改分
③ 前端不判断 —— 看按钮，别猜
\`\`\`

## 附录 C：遇到问题的排查顺序

\`\`\`
① 按钮是灰的？
   → 鼠标放上去看原因。那是服务器给的答案，别猜。

② 操作被拒了？
   → 看返回的错误码：
      403 forbidden        → 你没权限（或者被封禁了）
      409 invalid_state    → 当前状态不允许这个动作
      409 quota_exceeded   → 你的额度满了
      429 rate_limited     → 太快了，等等再来
      404 not_found        → 不存在，或者你没权限看（系统故意不区分）

③ 码验证失败？
   → 让对方去【我的完成码】看最新的码（你可能改过分配，旧码作废了）

④ 分数不对？
   → 看【声誉明细】。如果确实算错了，找管理员，走争议流程。

⑤ 什么都试过了？
   → 找管理员。带上：任务序号、时间、你做了什么、看到什么。
\`\`\`
